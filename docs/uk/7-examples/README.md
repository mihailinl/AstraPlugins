# Приклади

> Переклад. Джерело істини — [docs/en](../../en/7-examples/README.md); за розбіжності відповідає англійська версія.

Одинадцять плагінів у [`examples/`](../../../examples/), усі перенесені на
поточні SDK і всі збираються в CI. Читайте той, що робить те, що потрібно
вам, а потім починайте із заготовки, а не з прикладу — приклади не несуть
шаблонного коду, який вам довелося б видаляти.

Кожен запис нижче читається з власного `plugin.toml` цього плагіна.

## З чого читати спершу

| | Мова | Можливості | Дозволи | Чому саме цей |
|---|---|---|---|---|
| [`dice-roller`](../../../examples/dice-roller/) | Rust | `tools`, `actions`, `triggers` | `fire_trigger` | Еталонний плагін. Три можливості, один дозвіл, і набір тестів, що показує, як тестується кожна |
| [`json-tools`](../../../examples/json-tools/) | TypeScript | `tools`, `actions`, `triggers` | `set_variable` | Та сама форма на TypeScript, і приклад, чиї тести доходять до рівня дроту |
| [`text-utils`](../../../examples/text-utils/) | Python | `tools`, `actions`, `triggers` | `fire_trigger` | Та сама форма на Python |

Ці три — навмисно один і той самий плагін трьома способами. Якщо ви
обираєте мову, прочитайте всі три і оберіть екосистему, з якої хочете
тягнути бібліотеки — кожна можливість доступна в кожному SDK.

## Голосові провайдери

| | Мова | Можливості | Чому саме цей |
|---|---|---|---|
| [`tone-tts`](../../../examples/tone-tts/) | Rust | `tts` | Провайдер синтезу мовлення, що говорить писками. Тест проводки, а не голос |
| [`mock-stt`](../../../examples/mock-stt/) | Rust | `stt` | Повертає детермінований транскрипт, що описує отримане аудіо. Bidi-потік мінус розпізнавач |
| [`echo-stt`](../../../examples/echo-stt/) | Rust | `stt` | Нічого не транскрибує і програє ваш мікрофон назад через процес плагіна. Щоб почути, що демон реально вам надсилає |

`tone-tts` і `mock-stt` — два з чотирьох плагінів, які завдання перевірки
відповідності прогонить на кожному запуску CI, саме тому що вони вправляють
хуки, яких більше ніхто не торкається.

## UI і `dom_access`

Вони запускають код всередині вікна Astra. Саме через них [у
сайдлоадингу немає стелі дозволів](../5-publish/sideload.md): `dom_access`
неможливо розробляти жодним іншим способом.

| | Мова | Можливості | Чому саме цей |
|---|---|---|---|
| [`companion`](../../../examples/companion/) | Rust | `ui_contributions`, `dom_access` | Кіт, що літає по вікну і щось каже. Найменший повний UI-внесок |
| [`bad-apple`](../../../examples/bad-apple/) | Rust | `ui_contributions`, `dom_access` | Анімація *Bad Apple!!* у чотирьох режимах рендерингу. Постачає власні дані кадрів; див. її `SETUP.md` |
| [`doom`](../../../examples/doom/) | Rust | `ui_contributions`, `dom_access` | Сторінка з Doom, що працює на WebAssembly-рушії. Найкрайніше, чим може бути UI-внесок |

`companion` — четвертий плагін, який прогонить завдання перевірки
відповідності, для `ui_contributions`.

## Клієнти

Плагін `client` — це власний фронтенд чату — своя сесія, своя поверхня. Це
високоризикова можливість, і вона відхиляється безумовно для [локально
імпортованого файлу](../5-publish/local-install.md).

> **`web-chat` досі випереджає демон; `telegram-client` — уже ні.** Половина
> клієнтського шляху на боці демона не побудована: кожен плагін реєструється
> як `ClientType::PluginClient`, і перехоплювач авторизації відхиляє цю
> ідентичність на будь-якому gRPC-шляху поза `/astra.PluginHostService/`,
> тож `DaemonClient`, під який написаний `web-chat`, відповідає
> `permission_denied` на кожен виклик. Читайте його заради форми клієнтського
> плагіна — поверхні, потоку подій, i18n, — а не як те, що сьогодні можна
> запустити від початку до кінця. `telegram-client` переписаний на
> `Host::send_chat_message`: цей виклик іде в host-сервіс і працює, а чим за
> це платить міст — написано в першому розділі його README. Див.
> [розділ `Daemon` Rust SDK](../4-sdk/rust.md#daemon--присутній-у-sdk-відхиляється-демоном).

| | Мова | Можливості | Чому саме цей |
|---|---|---|---|
| [`telegram-client`](../../../examples/telegram-client/) | Rust | `client` | Повідомлення з Telegram туди, відповідь Astra потоком назад — єдиний робочий клієнтський шлях |
| [`web-chat`](../../../examples/web-chat/) | Rust | `client` | Вікно браузера, що спілкується з Astra. Щоб поспостерігати за синхронізацією кількох клієнтів |

## Платформи

Жоден з одинадцяти не оголошує блок `[platform]`, а отже демон вважає
кожен сумісним всюди — правильно для двох інтерпретованих, і те, що
*опублікований* нативний плагін мав би звузити. Див.
[платформи](../1-orientation/platforms.md).

| Мова | Що збирає реліз |
|---|---|
| Rust (дев'ять з них) | `linux-x64` **і** `windows-x64`, по одному бандлу на кожну |
| TypeScript (`json-tools`) | один бандл `noarch` |
| Python (`text-utils`) | один бандл `noarch` |

`doom` і `bad-apple` додатково постачають дані — WebAssembly-рушій, кілька
мегабайт кадрів — і їхній `SETUP.md` каже, звідки вони і як їх
регенерувати.

## Чим вони протестовані

| Рівень | Що запускається | Які приклади |
|---|---|---|
| Юніт | внутрішньопроцесний harness SDK, у власних тестах кожного прикладу | `dice-roller`, `mock-stt`, `text-utils`, `json-tools` |
| Збірка | кожен приклад збирається на кожному запуску CI | усі одинадцять |
| Відповідність | `astra-plugin test` запускає справжній процес проти мок-демона і прогонить кожен хук, який передбачають його можливості | `dice-roller`, `mock-stt`, `tone-tts`, `companion` |

Набір для перевірки відповідності обраний заради покриття таблиці хуків, а
не заради різноманітності — tools/actions/triggers, bidi-потік STT, TTS і
UI-внески. **У `ai_provider` немає прикладу, і тому він не покритий**, і
про це варто сказати вголос: прогалина в покритті, яку ніхто не називає,
стає тією, яку всі вважають закритою.

Приклади на Python і TypeScript поки не в завданні перевірки відповідності,
тому що їхні SDK не опубліковані, а прогін перевірки відповідності, що
наполовину встановлює SDK, звітує про встановлення, а не про плагін.
`astra-plugin test` керує процесом і їй байдуже, якою мовою він написаний,
тож вони приєднаються до завдання того дня, коли SDK будуть опубліковані.

## Запуск одного з них

<!-- doctest: cli -->
```bash
cd examples/dice-roller
astra-plugin check --strict
astra-plugin test
astra-plugin dev
```

`dev` потребує запущеної Astra і режиму розробника — спершу прочитайте,
[чого це коштує](../5-publish/sideload.md).
