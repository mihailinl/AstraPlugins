# Логи

> Переклад. Джерело істини — [docs/en](../../en/6-operate/logs.md); за розбіжності відповідає англійська версія.

Вивід плагіна може опинитися в трьох місцях, і знання, яке з них яке,
економить годину.

| | Куди йде | Хто може це побачити |
|---|---|---|
| `tracing::info!` / `logging.info(...)` (міст логування SDK) | пересилається демону як `PluginLog`, **і** в stderr | ви *і* користувач, у панелі логів Astra |
| `ctx.host().log_info(...)` — явний виклик | демону | ви і користувач |
| `println!` / голий stderr | stdout/stderr процесу, який захоплює демон | ви, через `astra-plugin logs` |

До появи мосту це були два різні набори, і цікаві рядки — паніка,
провалений запит, повтор — майже завжди опинялися в наборі, який
користувач бачити не міг.

## Читаємо їх

<!-- doctest: cli -->
```bash
astra-plugin logs
astra-plugin logs dice-roller -f
astra-plugin logs dice-roller -n 500 --daemon-addr 127.0.0.1:32000
astra-plugin logs --json
```

Без id вона читає `plugin.id` з маніфесту в `--path`. Це працює для
**встановлених** плагінів — випадку, який `astra-plugin dev` взагалі не
може обслужити.

Демон тримає **обмежений кільцевий буфер на плагін**, і `GetPluginLogs` —
унарний виклик над ним, тож `-f` — це опитування кожні 750 мс, а «нові»
рядки — це суфікс цього хвоста, що не продовжує попередній. Перезапуск
скидає буфер.

Запросити рядків більше, ніж тримає буфер, безпечно. `--json` друкує один
документ і виходить — це форма знімка; `-f` і `--json` не утворюють
корисну пару.

## Що пересилає SDK, а що ні

Шар `tracing`, який встановлює SDK, пересилає демону:

- **`INFO` і вище**, за замовчуванням. `ASTRA_PLUGIN_LOG_LEVEL` це міняє;
  `DEBUG` належить `RUST_LOG` і stderr, тому що панель — для користувача.
- **Не** транспортний стек — `h2`, `hyper`, `tonic`, `tower`, `rustls`,
  `tokio`. Надсилання рядка логу — це саме по собі RPC, а RPC, що логує,
  виробляє рядок логу: без цього виключення один `WARN` від `h2` стає
  нескінченним циклом.
- **Не більше, ніж тримає черга.** Канал обмежений, а надсилання
  неблокувальне, тож плагін у гарячому циклі втрачає рядки, а не створює
  зворотний тиск своїх обробників на демон.

### Python

`install_logging_bridge()` спрямовує стандартний модуль `logging` тим самим
шляхом. Використовуйте його замість `print`: SDK перемикає stdout на
**порядкову буферизацію**, тому що супервізор демона читає stdout, щоб
зрозуміти, що плагін живий, а блочна буферизація виводу колись призводила
до того, що супервізор вбивав здорові плагіни за тайм-аутом старту.

## Вмикаємо власне трасування CLI

`RUST_LOG` керує самою `astra-plugin`. Вона документувалася з версії 0.1 і
нічого не робила, поки не було встановлено підписника — кожна подія
`tracing`, яку випускали CLI та її залежності, йшла в нікуди.

<!-- doctest: cli -->
```bash
RUST_LOG=astra_plugin=debug astra-plugin check
RUST_LOG=debug astra-plugin build
```

За замовчуванням — `warn`, і йде в **stderr** — користувацький вивід CLI на
stdout, і рядок трасування там пошкодив би документ `--json`.

<!-- doctest: output from="astra-plugin doctor ." -->
```
  [ok  ] Why do I see no trace output from the CLI?
         RUST_LOG is unset, so only warnings and errors are printed.
         `RUST_LOG=astra_plugin=debug` turns on this CLI's own trace;
         `RUST_LOG=debug` turns on its dependencies' too.
```

## Файли на диску

| | Linux | Windows |
|---|---|---|
| Логи демона | `~/.config/astra/logs/` | `%APPDATA%\astra\astra\config\logs\` |
| Каталог конфігурації, який визначила CLI | спитайте `astra-plugin doctor` | спитайте `astra-plugin doctor` |

Файли логів демона датовані (`daemon.log.2026-08-05`). Власні рядки
плагіна з'являються там через `PluginLog`, а його сирий stdout/stderr — це
те, що `astra-plugin logs` читає з буфера демона в пам'яті — цей буфер не
файл, тож він не переживає перезапуск демона.

Питайте, а не припускайте, який каталог використовує ця машина: `doctor`
друкує той, що визначила CLI, і якщо Astra не згодна, значить ці двоє
визначили різні каталоги — а це вже сам по собі баг.

## Коли логів взагалі немає

Процес падає до того, як SDK встановить своє логування. Запустіть його
вручну:

<!-- doctest: cli -->
```bash
astra-plugin dev --standalone
```

Це запускає плагін напряму, а не через демон. Вона друкує, чого так
зробити не можна — плагін не може зареєструватися, тому що лише демон може
випустити токен, який вимагає `Register`.
