# Політика версіонування та застарівання

> Переклад. Джерело істини — [docs/en](../en/versioning.md); за розбіжності відповідає англійська версія.

Що означають цифри, як довго гарантовано продовжить працювати те, від чого
ви залежите, і де ця гарантія записана як дані, а не як обіцянка, яку
хтось має пам'ятати.

## Чотири числа, і лише одне з них — SDK

| Число | Де живе | Що каже |
| --- | --- | --- |
| **Версія SDK** | `astra-plugin-sdk/Cargo.toml`, `astra-plugin-sdk-python/pyproject.toml`, `astra-plugin-sdk-ts/package.json` | API написання, проти якого ви пишете код. У кожного пакета своя. |
| **Релізний потяг** | git-тег `sdk-v<VERSION>` | Один тег публікує всі три SDK разом. Називає версію **крейта Rust**. |
| **Версія протоколу** | `proto/PROTO_VERSION` (`protocol=1`), дзеркалюється як `PROTOCOL_VERSION` у кожному SDK | Контракт дроту між плагіном і демоном. |
| **Версія вашого плагіна** | ваш `plugin.toml` | Ваша. Реєстр впорядковує релізи за нею. |

Три версії SDK навмисно не тримаються рівними: один тег `sdk-v<VERSION>`
публікує ту версію, яка записана в маніфесті кожного пакета, а
`astra-plugin-macros` виходить **раніше** за Rust SDK, який залежить від нього
за версією. Які це номери сьогодні, на цій сторінці не написано. Раніше вона
називала поточний потяг і ще місяць називала `sdk-v0.7.0` після того, як
вийшов `sdk-v0.7.1`, — тому номери живуть в одному місці, у таблиці
[Publication state](../../README.md#publication-state) у README, де зв'язка C23
звіряє колонку *In this tree* з маніфестами, а C23b — колонку *Published* з
crates.io, PyPI і npm.

Номер версії відповідає на питання «проти якого API я пишу код», тож у
пакета з меншою кількістю ламаючих релізів число менше. Що гарантує потяг —
це що пакети, які поділяють тег, говорять на **тому самому протоколі** і
реалізують ті самі хуки — саме для цього існують `spec/hooks.yaml` і
перевірка паритету.

## SemVer, нижче 1.0

Усі три пакети нижче 1.0 і слідують трактуванню SemVer для 0.x:

- **minor** (`0.5 → 0.6`) — може зламати сумісність вихідників. Читайте
  CHANGELOG.
- **patch** (`0.6.0 → 0.6.1`) — лише виправлення багів і додавання. Якщо
  patch-реліз перестає компілювати ваш плагін — це баг у SDK, заведіть
  issue.

Версія протоколу окрема і рухається сама по собі. Це ціле число, не
SemVer, і правило для неї не «читайте changelog», а механізм:

- Хук, якого немає у співрозмовника, відповідає `UNIMPLEMENTED`, що
  протокол визначає як *відсутність*. Демон читає це саме так і продовжує
  роботу. Саме тому новіший плагін працює зі старішим демоном і навпаки.
- `MIN_SUPPORTED_DAEMON_PROTOCOL` у кожному SDK — це найстаріший демон, з
  яким цей SDK зареєструється. Нижче цього плагін виходить з реченням, що
  називає рішення, а не падає на першому ж виклику.

## Згенеровані типи протоколу

Повідомлення протоколу, які віддає кожен SDK, — `astra_plugin_sdk::proto::*`
у Rust, класи повідомлень `_pb2` у Python, дескриптор, який завантажує
TypeScript SDK, — генеруються з `proto/plugin.proto`, власного зрізу демона,
який пересинхронізується щоразу, коли протокол демона росте. Правило версій
для них:

| Зміна згенерованого типу | Слот |
| --- | --- |
| додано поле або повідомлення | patch — додавання |
| поле видалено, перейменовано, перенумеровано або змінило тип | minor — поломка |

**Що покриває обіцянка patch у Rust:** побудову повідомлення з
`..Default::default()` або через `Default::default()` з подальшим
присвоюванням полів. Вона **не** покриває вичерпний літерал структури — той,
що перелічує кожне поле і не містить `..`, — який нове поле ламає помилкою
`E0063 missing fields`, так само як не покрито `match` по enum з
`#[non_exhaustive]`. `astra-plugin new` пише форму з `..Default::default()`.
Класи повідомлень Python приймають іменовані аргументи, а TypeScript SDK читає
дескриптор під час виконання, тож у цих двох нове поле нічого не ламає.

Чому нове поле — не minor: кожна синхронізація зрізу демона додає поля — 37 у
вже наявних повідомленнях між `sdk-v0.7.1` і 0.7.2, — тож minor на кожне поле
зробив би minor з кожної синхронізації, і слот minor перестав би означати *ваш
код може перестати компілюватися*. Чому не `#[non_exhaustive]` на
згенерованих структурах, що зробило б правило правилом компілятора: він
забороняє і `..Default::default()` поза крейтом, тобто зламав би літерал
кожного плагіна сьогодні, щоб уберегти його від поломки завтра. Сумісність на
дроті — взагалі не завдання цього правила; це завдання цілого числа протоколу,
вище. Типи, які SDK пише вручну, лишаються під звичайним правилом, тому
`Invocation` позначено `#[non_exhaustive]`.

## Політика застарівання

Коли щось в API написання йде геть:

1. **Воно оголошується застарілим мінімум на два minor-релізи і мінімум на
   один календарний квартал**, дивлячись що довше. Застаріло в 0.6 означає
   видаляється в 0.8, і не раніше, ніж пройдуть три місяці. Плагін, що
   збирається сьогодні, продовжує збиратися щонайменше ще один реліз, на
   який ви можете спланувати.
2. **Примітка про застарівання називає заміну.** Не «застаріло», не
   «використовуйте новий API» — конкретний ідентифікатор, який треба
   написати натомість, або слова *заміни немає* і чому її немає.
   Застарівання, що велить зупинитися, не сказавши куди йти, відправляє вас
   до трекера задач.
3. **Видалення йдуть під заголовком `BREAKING` у CHANGELOG**, у пакеті, що
   їх видалив, називаючи, що видалено і що прийшло на заміну. Ніщо не
   видаляється в patch-релізі.

Як виглядає «застаріло» кожною мовою:

| | Як позначено | Що ви бачите |
| --- | --- | --- |
| Rust | `#[deprecated(since = "0.6.0", note = "…")]` | попередження компілятора в місці використання, з приміткою |
| Python | `DeprecationWarning` у місці виклику | `python -W error::DeprecationWarning` перетворює це на збій, на якому можна зав'язати CI |
| TypeScript | `/** @deprecated … */` | закреслення у вашому редакторі і примітка при наведенні |

Застарівання — це попередження, ніколи не помилка. Якщо реліз змушує
застарілий код *перестати компілюватися* — це видалення, і видалення
слідують правилу 3.

### Що застаріло прямо зараз

| Що | Застаріло в | Видалено в | Заміна |
| --- | --- | --- | --- |
| Rust: уся поверхня трейта 0.5, як `astra_plugin_sdk::compat` | 0.6.0 | 0.8.0 | `PluginCapability` (0.6): `&PluginContext`, `Result<_, ToolError>`, `type Config`. Див. [migration-0.6.md](migration-0.6.md) |
| Rust: `PluginCapability::source_id()` | 0.6.0 | 0.8.0 | Передавайте id в `Host::send_chat_message`; демон перестав фільтрувати за id джерела |
| Rust: `compat::ToolResult` / `ActionResult` / `UiCallResult` | 0.6.0 | 0.8.0 | `Result<String, ToolError>` |
| Rust: псевдоніми `compat::HostClient` / `DaemonClient` | 0.6.0 | 0.8.0 | `ctx.host()` / `ctx.daemon()` |
| Python: `dict` там, де очікується dataclass можливості | 0.5.0 | 0.7.0 | Dataclass — `VoiceInfo`, `ToolDef`, … — або його `to_proto()` |
| TypeScript: псевдонім типу `UiPanel` | 0.5.0 | 0.7.0 | `UiContribution` |
| Хук: `AiGetModels` | 0.6.0 | 0.8.0 | Заміни немає — ніщо в демоні не питає у плагіна, які в нього моделі |

Дві виноски, тому що обидві — саме те, для запобігання чому існує ця
політика:

- `DeprecationWarning` у Python для dict'ів каже, що вони приймаються «ще
  один minor-реліз». **Зобов'язуюче число — те, що в таблиці**: два minor і
  один квартал, тож не раніше 0.7.0.
- `UiPanel` було оголошено застарілим у TypeScript взагалі без записаної
  версії. Тут він датований 0.5.0 — першим релізом, що каже про це
  письмово, — і видаляється починаючи з 0.7.0.

## Політика — це дані

Правила, що живуть лише в документі, забуваються рівно в той момент, коли
вони важливі: у релізі, де хтось видаляє річ. Тож половина політики, що
стосується кожного хука, — це колонка в
[`spec/hooks.yaml`](../../spec/hooks.yaml):

<!-- doctest: illustrative reason="one row of spec/hooks.yaml, quoted; the file it belongs to is the source of truth and is checked by tools/parity/check.py" -->
```yaml
  - rpc: AiGetModels
    ...
    routing: deprecated
    deprecated_in: "0.6"
    removed_in: "0.8"
    note: "… Deprecated in 0.6, removed in 0.8, and there is no replacement: nothing in the daemon asks a plugin what models it has, and AiComplete carries the chosen model on the request."
```

`tools/parity/spec.py` перевіряє це при кожному розборі — а отже, при
кожному запуску `gen.py`, кожному запуску `check.py`, і, відповідно, при
кожному запуску CI:

| Правило | Який збій запобігає |
| --- | --- |
| `routing: deprecated` вимагає `deprecated_in` | хук, що «застарів» уже роки без прив'язаної дати |
| `deprecated_in` вимагає `removed_in` | застарівання без кінця, що просто грубий коментар |
| `removed_in` ≥ `deprecated_in` + 2 minor | видалення, що трапляється раніше, ніж у когось з'явився реліз для міграції |
| `note` застарілого рядка називає інший rpc або каже `no replacement` | «застаріло» без зворотної адреси |

Помилитеся — і перевірник скаже про це, з номером рядка:

<!-- doctest: illustrative reason="the failure `tools/parity/check.py` prints for a hooks.yaml row that violates the removal policy; no such row exists in the tree, so producing it means editing hooks.yaml first" -->
```
spec/hooks.yaml is malformed:
  hooks.yaml:336: `AiGetModels` is deprecated in 0.6 and removed in 0.7 — the policy is
  2 minors and one quarter minimum, so the earliest removal is 0.8
```

Версії в цих колонках — це **minor-версії SDK**, не версії протоколу:
`0.6` — це число з вашого `Cargo.toml` і число, під яким занесений
заголовок CHANGELOG. Квартальна половина політики — це календар, а не дані
— її датує релізний потяг, а цей документ — те місце, де це записано.

## Що цим нічого не покрито

- **Власна поведінка демона.** Інтерфейс Astra, розкладка її конфігурації
  і її внутрішні сервіси — не API плагіна. На що плагін може покладатися —
  це протокол, хуки в `spec/hooks.yaml`, і дозволи в його маніфесті.
- **Усе, позначене `#[doc(hidden)]`, `_private`, або експортоване для
  тестового harness.** Може змінитися в patch.
- **Немаршрутизовані (`unrouted`) хуки.** Хук може існувати в proto і в
  усіх трьох SDK і не мати точки виклику в демона — сьогодні це
  `TtsSynthesizeStream`. Реалізувати його безпечно і безкоштовно;
  *покладатися* на те, що демон його викличе, не підтримується, поки його
  `routing:` не скаже `live`.

## Якщо вікна застарівання недостатньо

Скажіть про це перш ніж воно закриється. Видалення, що вже трапилося, — це
видалення; видалення, що все ще `removed_in` у `spec/hooks.yaml`, — це
дата, а дати можна зсунути, якщо хтось вчасно скаже чому.
