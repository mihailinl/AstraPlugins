# Що таке плагін

> Переклад. Джерело істини — [docs/en](../../en/1-orientation/what-is-a-plugin.md); за розбіжності відповідає англійська версія.

Плагін — це **окрема програма**, яку запускає демон Astra і яка спілкується з
демоном по gRPC на localhost. Це не бібліотека, вона не завантажується в
адресний простір Astra, і це не скрипт, який Astra інтерпретує. Astra запускає
її так само, як це зробив би шелл, — з аргументами командного рядка, — а
зупиняє, попросивши завершитися, і вбиває групу процесів, якщо та не
завершилася сама.

Цей єдиний факт визначає майже все інше:

- **Писати можна будь-якою мовою**, що вміє gRPC. Тут постачаються три SDK —
  Rust, Python, TypeScript — і вони перебувають у стані
  [повного паритету](../reference/parity.md): усі 35 хуків у всіх трьох.
- **У плагіна ваші права, а не менші.** Див. [модель безпеки](security.md).
- **Він погано переживає власні баги, а Astra — взагалі ніяк.** Паніка
  всередині обробника перехоплюється й повертається як помилка, а не вбиває
  процес (`astra-plugin-sdk/src/panics.rs`); падіння всього процесу виявляється
  перевіркою здоров'я демона протягом 15 секунд.

## Два напрямки

Усе, що робить плагін, належить до одного з двох напрямків — це окремі
системи з окремими назвами в `plugin.toml`.

| | Напрямок | Розділ маніфесту | Відповідає на |
|---|---|---|---|
| **Можливості (Capabilities)** | демон → плагін | `[capabilities]` | Що плагін реалізує і що Astra може викликати *всередині* нього |
| **Дозволи (Permissions)** | плагін → демон | `[permissions]` | Які RPC хоста плагін може викликати *назовні* |

Раніше для обох було одне слово, через що `dom_access` — найнебезпечніше, що є
в системі, — виявлявся тим, що плагін видавав сам собі, просто оголосивши
його. Тепер це два різні слова. Оголошення `[capabilities] event_handlers =
true` не дає права підписуватися на події; це робить
`[permissions] subscribe_events`, і лише після згоди користувача.

`[permissions]` працює за принципом **заборонено все, що явно не дозволено**:
без розділу взагалі плагін може викликати лише `Register`, `PluginLog`,
`GetPluginSelfConfig` і `GetDaemonInfo`, і нічого більше
([`spec/permissions.md` §2](../spec/permissions.md)).

## Десять можливостей

Кожен ключ — булевий, за замовчуванням `false`, і зобов'язує вас обслуговувати
певні хуки. У правій колонці — *обов'язкові*; необов'язкові — у
[таблиці паритету](../reference/parity.md).

| Ключ `[capabilities]` | Чим стає ваш плагін | Хуки, які потрібно обслужити |
|---|---|---|
| `tools` | набір функцій, які може викликати модель | `ListTools`, `CallTool` |
| `tts` | провайдер синтезу мовлення в налаштуваннях голосу | `TtsSynthesize`, `TtsListVoices` |
| `stt` | провайдер розпізнавання мовлення | `SttProcess`, `SttGetLanguages` |
| `ai_provider` | бекенд моделі | `AiComplete` |
| `actions` | кроки в редакторі команд | `ExecuteAction`, `GetPluginActionTypes` |
| `triggers` | типи тригерів, на які можуть підписуватися команди | `GetPluginTriggerTypes`, `FireTrigger` |
| `ui_contributions` | панелі, сторінки й оверлеї у вікні Astra | `GetUiContributions` |
| `event_handlers` | підписник на події демона | `SubscribeEvents` |
| `client` | власний клієнт чату | `SendChatMessage` |
| `dom_access` | код, що виконується всередині вікна Astra | жодного — це рішення про рендеринг, а не хук |

Джерело: [`reference/manifest.md`](../reference/manifest.md), згенеровано з
крейта, яким демон розбирає ваш маніфест. `ui_panels` — не можливість і ніколи
нею не була: три приклади з постачання оголошували її, serde тихо відкидав
невідомий ключ, і єдиним симптомом було те, що `astra-plugin check` повідомляв
про відсутність усіх можливостей взагалі. Саме тому `[capabilities]` відхиляє
невідомі ключі.

## Як виглядає маніфест

Найменший корисний маніфест — плагін з інструментами, без дозволів і без
нічого зайвого:

<!-- doctest: toml-manifest -->
```toml
[plugin]
id = "dice-roller"
name = "Dice Roller"
version = "0.1.0"
description = "Roll dice from chat."
author = "You"
license = "MIT"

[entry]
command = "target/release/dice_roller"

[capabilities]
tools = true
```

Плагін, що спрацьовує за тригером, зобов'язаний запросити дозвіл, а `reason` —
це те, що користувач прочитає, коли Astra попросить його дати згоду:

<!-- doctest: toml-manifest -->
```toml
[plugin]
id = "dice-roller"
name = "Dice Roller"
version = "0.1.0"
description = "Roll dice, and fire a trigger when one comes up."
author = "You"
license = "MIT"
homepage = "https://github.com/you/dice-roller"

[entry]
command = "target/release/dice_roller"

[capabilities]
tools = true
triggers = true

[permissions]
fire_trigger = { reason = "Fires the trigger you configure when a roll completes" }
```

Кожен розділ і ключ: [`reference/manifest.md`](../reference/manifest.md).

## Чого плагін не може

- **Не може видати собі дозвіл — після встановлення.** Розділ `[permissions]`
  — це запит. Для плагіна, встановленого з реєстру або імпортованого як файл,
  виданий набір дозволів обчислює демон, виходячи з того, звідки плагін
  з'явився, і зберігає його там, куди плагін не може писати, — сам маніфест
  лежить у каталозі плагіна, який плагін може редагувати. **Сайдлоаднутий
  плагін — виняток**: на цьому рівні маніфест *і є* записом про згоду, і стелі
  немає, тож плагін може розширити власні дозволи, відредагувавши власний
  файл. Див.
  [модель безпеки](security.md#звідки-взявся-плагін-визначає-його-стелю).
- **Не може напряму дістатися до `ChatService` Astra.** Токен сесії, який
  плагін отримує під час реєстрації, обмежений `PluginHostService`. Керування
  ходом ШІ йде через `SendChatMessage`, яке закрите дозволом
  `send_chat_message` і належить до високоризикових.
- **Не може покладатися на немаршрутизований хук.** Хук може існувати в proto
  й у всіх трьох SDK і не мати точки виклику в демоні: сьогодні це
  `TtsSynthesizeStream`. Реалізувати його — безкоштовно; покладатися на те, що
  його викличуть, не підтримується, поки
  [таблиця паритету](../reference/parity.md) не скаже `live`.
- **Не може бути встановлений на платформу, для якої в нього немає бандла.**
  Див. [платформи](platforms.md).
