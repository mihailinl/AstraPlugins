# Довідник `plugin.toml`

Кожен розділ, кожен ключ і все, що щось відхиляє. Виведено з
[`astra-plugin-manifest`](../../../astra-plugin-cli/vendor/astra-plugin-manifest/src/manifest.rs)
— крейта, яким демон розбирає ваш маніфест, завендореного в цей
репозиторій і утримуваного побайтово ідентичним копії Astra через
`tools/check-manifest-crate.sh`. Другого визначення маніфесту, здатного
розійтися з цією сторінкою, не існує.

Повний маніфест плагіна, розібраний з `plugin.toml`.

Навмисно **не** `deny_unknown_fields`: розділи додаються з релізами —
`[permissions]` був останнім — і старіший демон зобов'язаний пропускати
розділ, якого не знає, а не відхиляти плагін. `[capabilities]` — виняток,
і [`Capabilities`] пояснює чому.

## Розділи

| Розділ | Обов'язковий | Що оголошує |
|---|---|---|
| [`[plugin]`](#plugin) | **так** | Ідентичність плагіна і метадані. |
| [`[entry]`](#entry) | **так** | Як запускати процес плагіна. |
| [`[capabilities]`](#capabilities) | ні | Що плагін **реалізує**, демон→плагін. |
| [`[permissions]`](#permissions) | ні | Що плагін просить **викликати**, плагін→демон — і це саме *прохання*. |
| [`[config]`](#config) | ні | JSON Schema для конфігурації плагіна (авто-генерує UI налаштувань). |
| [`[dependencies]`](#dependencies) | ні | Таблиця рядків, без власної схеми. |
| [`[platform]`](#platform) | ні | Вимоги до платформи — `[platform]` у `plugin.toml`. |
| [`[build]`](#build) | ні | Метадані збірки, додані `astra-plugin build`. |
| [`[ui]`](#ui) | ні | Визначення UI-внесків, оголошені в plugin.toml. |

Розділ, якого ця Astra не знає, — **зберігається, а не відхиляється** —
розділи додаються з релізами, і старіший демон повинен вміти пропустити
один з них. `[capabilities]` — єдиний виняток, і причина нижче.

| `call_timeout_secs` | ціле | ні | відсутнє | Скільки демон чекає `CallTool` / `ExecuteAction`, перш ніж здатися, у секундах. |

† несе правило, що відхиляє маніфест безумовно — див.
[що відхиляється](#що-відхиляється) для умови і повідомлення.

**`plugin.min_astra_version`.** Найстаріша Astra, на якій працює цей
плагін, як версія semver (`"0.9.0"`). Порожньо = немає вимоги.

Її *синтаксис* перевіряється через [`PluginManifest::validate`] всюди. Її
*значення* порівнюється з працюючою Astra лише в збірці, яка сама її
знає — див. [`crate::host_astra_version`]. Вона існувала цілий реліз як
поле, яке розбиралося і ніколи не читалося, тож плагіну, що потребував
фічі демона, якої в хоста не було, встановлювався чисто, а потім
провалювався рівно на тому виклику, для якого вона потрібна, —
користувач читає це як «цей плагін зламаний».

**`plugin.call_timeout_secs`.** Скільки демон чекає `CallTool` /
`ExecuteAction`, перш ніж здатися, у секундах. `None` → власний
`PLUGIN_CALL_TIMEOUT` демона.

Плагін, що є фронтом для довгоживучого агента, зобов'язаний це оголосити:
значення за замовчуванням демона навмисно нижче, ніж «вічність», і у
плагіна, чий власний бюджет роботи його перевищує, результат буде
викинутий, поки його підпроцес продовжує працювати (`coding-agents`
постачає значення за замовчуванням 180 с). На плагін, так само як
`McpServerConfig::timeout_secs` — на сервер.

## `[capabilities]`

Що плагін **реалізує**, демон→плагін.

**Невідомий ключ тут валить весь маніфест.** `Capabilities` —
`#[serde(deny_unknown_fields)]`, єдиний такий серед розділів: він цілком
складається з булевих ознак згоди, тож одруківка інакше читалася б рівно
як `false`, і плагін встановився б, нічого не оголосивши. Це не гіпотеза —
три приклади з постачання оголошували `ui_panels`, ім'я, якого ніколи не
було в жодного демона, і єдиним симптомом було те, що `astra-plugin
check` друкував «No capabilities enabled».

Кожен ключ — булевий і за замовчуванням `false`. Права колонка —
з'єднання з [`spec/hooks.yaml`](../../../spec/hooks.yaml): хуки, які ваш
плагін зобов'язаний обслуговувати, щоб можливість взагалі працювала.
`optional`-хуки тут опущені; [`parity.md`](./parity.md) несе їх усі.

| Ключ | Хуки, які зобов'язує реалізувати |
|---|---|
| `tools` | `ListTools`, `CallTool` |
| `tts` | `TtsSynthesize`, `TtsListVoices` |
| `stt` | `SttProcess`, `SttGetLanguages` |
| `ai_provider` | `AiComplete` |
| `client` | `SendChatMessage` |
| `actions` | `ExecuteAction`, `GetPluginActionTypes` |
| `triggers` | `GetPluginTriggerTypes`, `FireTrigger` |
| `ui_contributions` | `GetUiContributions` |
| `event_handlers` | `SubscribeEvents` |
| `dom_access` | немає |

**Імена, які ніколи не були справжніми:**

- `ui_panels` → `ui_contributions`

## `[permissions]`

Що плагін просить **викликати**, плагін→демон — і це саме *прохання*.

Відсутність означає відсутність RPC хоста понад завжди дозволений
стартовий набір (§5.6). Набір, який плагін реально тримає, обчислює демон
з його походження, і для плагіна із записом довіри він ніколи не
читається звідси: маніфест лежить у власному каталозі плагіна, куди
плагін може писати.

Кожен ключ — id дозволу, а кожне значення — таблиця.

Id, якого ця Astra не знає, зберігається і бездіє: пряма сумісність, а
`permissions_hash` обчислюється по цих байтах трьома реалізаціями, тож
читач, що відкинув нерозпізнаний ключ, розійшовся б з двома іншими щодо
того, що було підписано.

| Id | Закриває | Свій чекбокс згоди | Відхиляється для локального імпорту | Що дає |
|---|---|---|---|---|
| `fire_trigger` | `FireTrigger` | ні | ні | Запускати збережені автоматизації користувача. |
| `subscribe_events` | `SubscribeEvents` | ні | ні | Отримувати події демона. |
| `set_variable` | `SetVariable` | ні | ні | Писати в контекст змінних демона (у просторі імен викликаючого плагіна). |
| `send_chat_message` | `SendChatMessage` | **так** | **так** | Керувати ходом ШІ. |
| `push_to_ui` | `PushToUi` | **так** | ні | Надсилати подію у вікно Astra. |
| `set_theme_contribution` | `SetThemeContribution` | **так** | **так** | Переоформляти весь застосунок. |
| `dom_access` | — | **так** | **так** | Виконувати власний код плагіна всередині вікна Astra, з доступом до бесід користувача та інтерфейсу будь-якого іншого плагіна. |
| `client` | — | **так** | **так** | Виступати фронтендом клієнта (власна поверхня чату, власна сесія). |

*Закриває* — це RPC хоста, який демон відхиляє без цього дозволу, з
[`spec/hooks.yaml`](../../../spec/hooks.yaml); правило паритету R6 звіряє
цю колонку з власним `HOST_RPC_PERMISSIONS` демона — таблицею, яку читає
`require_permission`. Порожня комірка — це дозвіл **поверхні**, що не
закриває жоден RPC: `dom_access` визначає, як рендериться UI-внесок, а
`client` — це стеля можливості.

*Відхиляється для локального імпорту* — це стеля для файлу `.astraplugin`,
який користувач імпортував вручну, а не встановив з каталогу: ці id
відкидаються безумовно, без попередження. Каталог з вихідним кодом,
завантажений при увімкненому режимі розробника, навмисно не обмежений
стелею — це цикл розробки для UI-плагінів.

### Значення ключа дозволу

| Ключ | Тип | Обов'язковий | За замовчуванням | Що це |
|---|---|---|---|---|
| `reason` | рядок | ні | `""` | Власні слова автора, що рендеряться *підпорядковано* мітці, яка належить застосунку (§4.3: у лапках, простим текстом, ≤140 символів, завжди з префіксом «The author says:»). |
| `types` | масив рядків | ні | порожньо | `subscribe_events.types` — запитувані типи подій. |
| `scopes` | масив рядків | ні | порожньо | `set_variable.scopes` — `"plugin"` / `"session"` / `"persistent"`. |

**`<permission>.reason`.** Власні слова автора, що рендеряться
*підпорядковано* мітці, яка належить застосунку (§4.3: у лапках, простим
текстом, ≤140 символів, завжди з префіксом «The author says:»). Це
ніколи не сама мітка — формулювання фіксуються в постачанні Astra і не
повинні бути налаштовуваними через лістинг.

**`<permission>.types`.** `subscribe_events.types` — запитувані типи
подій.

**Список дозволених, і порожній не дозволяє нічого.** Див.
[`Permissions::event_types`].

**`<permission>.scopes`.** `set_variable.scopes` — `"plugin"` /
`"session"` / `"persistent"`. Зарезервовано; демон сьогодні розділяє за
простором імен кожен запис плагіна за його id, тож це поки нічого не
звужує, але розбирається, щоб маніфест, що це оголошує, хешувався
однаково всюди.

**`fire_trigger`.** `PluginHostService.FireTrigger` — запускати збережені
автоматизації користувача.

**`subscribe_events`.** `PluginHostService.SubscribeEvents` — отримувати
події демона.

Несе аргумент: [`PermissionRequest::types`] — це **список дозволених**
типів подій, і його застосовує демон, а не фільтр, який надсилає плагін.
Без цього кожен підписник отримував кожну подію — включно з
`speech_recognized`, яка несе транскрипти користувача.

**`set_variable`.** `PluginHostService.SetVariable` — писати в контекст
змінних демона (у просторі імен викликаючого плагіна).

**`send_chat_message`.** `PluginHostService.SendChatMessage` — керувати
ходом ШІ. **Високий ризик.**

**`push_to_ui`.** `PluginHostService.PushToUi` — надсилати подію у вікно
Astra. **Високий ризик.**

**`set_theme_contribution`.** `PluginHostService.SetThemeContribution` —
переоформляти весь застосунок. **Високий ризик.**

**`dom_access`.** Виконувати власний код плагіна всередині вікна Astra, з
доступом до бесід користувача та інтерфейсу будь-якого іншого плагіна.
**Високий ризик, і той, для якого §4.3 дає другий екран.**

**`client`.** Виступати фронтендом клієнта (власна поверхня чату, власна
сесія). **Високий ризик.**

## `[dependencies]`

Вільна таблиця `ім'я = "вимога до версії"`. Обидві половини — рядки, і
крейт читає їх саме так — `HashMap<String, String>`, без схеми, без
розв'язання залежностей, і ніщо з неї нічого не встановлює. `astra-plugin
check` перелічує оголошене і попереджає, коли вимога порожня; це весь
її ефект.

## `[platform]`

| Ключ | Тип | Обов'язковий | За замовчуванням | Що це |
|---|---|---|---|---|
| `os` | масив рядків | ні | порожньо | — |
| `arch` | масив рядків | ні | порожньо | — |

**`KNOWN_OS_VALUES`** — `linux`, `windows`, `macos`

Значення `os`, які може називати `[platform] os = [...]`, у словнику, на
якому говорить [`current_platform`].

Ширше, ніж набір, для якого Astra постачає демон: оголошення `os =
["macos"]` — це твердження про плагін, а не заява, що хост існує, і
валідатор, що відхиляє це, відхиляв би коректний маніфест.

**`KNOWN_ARCH_VALUES`** — `x86_64`, `aarch64`

Значення `arch`, які може називати `[platform] arch = [...]`.

**`RESERVED_PLATFORM_KEYS`** — `linux-x64`, `windows-x64`, `linux-arm64`,
`windows-arm64`, `macos-x64`, `macos-arm64`, `noarch`

Кожен ключ артефакту, зарезервований схемою реєстру, у порядку, в якому
їх повинен видавати генератор.

Лише [`platform_key_for`] вирішує, які з них приймає *працюючий демон*, і
він приймає два. Решта зарезервовані, щоб формат індексу ніколи не
довелося змінювати, якщо Astra пізніше постачить демон для цих хостів, і
щоб валідатор реєстру міг відхилити одруківку (`mac-arm64`,
`linux-amd64`) замість того, щоб записати ключ, який демон ніколи не буде
шукати.

**Зарезервовано не означає підтримується.** Workflow релізу Astra не
збирає ні демон для macOS, ні для arm64, тож у бандла, опублікованого під
`macos-x64`, `macos-arm64`, `linux-arm64` або `windows-arm64`, немає
хоста для запуску. Генератор, що видає такий ключ, публікує файл, який
ніхто не може встановити.

`noarch` — це випадок інтерпретованої мови (TypeScript, Python). Він
зарезервований тут для валідаторів, але демон його **не** шукає: згідно
зі специфікацією бандла індекс записує той самий URL і дайджест під
кожним *підтримуваним* ключем платформи, тож `noarch`-бандл знаходиться
під `linux-x64` / `windows-x64`, як і будь-який інший.

Ніщо в шляху виконання демона не читає цей список — його споживачі — це
генератор індексу в репозиторії реєстру, `check` CLI, і тест нижче, що
утримує обидві половини чесними. Він лежить поряд з функцією, що вирішує,
який з цих ключів справжній, тому що це єдине місце, де ці два факти
можна прочитати разом.

## Що відхиляється

Кожна відмова, яку може виробити `PluginManifest::validate`, з умовою, що
її викликає. Умови — це самі вирази Rust: `plugin.id` стає компонентом
шляху — `<plugins_dir>/<id>/`, що створюється і пізніше видаляється через
`remove_dir_all` — тож перефразовувати правило про набір символів ця
сторінка не готова.

| Маніфест відхиляється, коли | Повідомлення |
|---|---|
| `self.plugin.id.is_empty()` | plugin.id is required |
| `self.plugin.name.is_empty()` | plugin.name is required |
| `self.plugin.version.is_empty()` | plugin.version is required |
| `self.entry.command.is_empty()` | entry.command is required |
| `!self.plugin.id.chars().all(\|c\| c.is_ascii_lowercase() \|\| c.is_ascii_digit() \|\| c == '-')` | plugin.id must be lowercase alphanumeric with hyphens: '{}' |
| `self.plugin.id.ends_with('.') \|\| self.plugin.id.ends_with(' ')` | plugin.id must not end with a dot or space: '{}' |
| `is_reserved_device_name(&self.plugin.id)` | plugin.id '{}' is a reserved Windows device name |
| `not (running >= required)` | Plugin '{}' requires Astra {} or newer, but this is Astra {}. Update Astra, or install a build of the plugin that supports {}. |
| ``semver::Version::parse(required)` returns Err` | plugin.min_astra_version '{}' is not a semver version (expected e.g. "0.9.0") |

`min_astra_version` — єдине правило з двома половинами. Його
**синтаксис** перевіряється всюди, включно з `astra-plugin check`:
значення, що не є версією semver, — це оголошене обмеження, яке нічого
не обмежує. Його **значення** порівнюється лише в збірці, яка сама є
Astra, — інструмент, що відмовляється дивитися на плагін, тому що той
націлений на новіший демон, ніж сам інструмент, був би безглуздям.
