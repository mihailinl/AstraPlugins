# Плагіни музичних сервісів

> Переклад. Джерело істини — [docs/en](../en/music-provider-plugins.md); за розбіжності відповідає англійська версія.

Плагін музичного сервісу оголошує `music_provider = true` у розділі
`[capabilities]` свого `plugin.toml`. Після цього він стає джерелом
**медіасесій** для Astra: музичний віджет, Dynamic Island і медіаінструменти
асистента (`get_now_playing`, `control_media`, `play_music`, `get_music_queue`)
дістають до сервісів, з якими він працює, — Web API Spotify, локальний API
десктопного плеєра, міст у браузер — і можуть вподобати трек У САМОМУ сервісі,
прочитати його чергу, шукати в каталозі й запускати відтворення там.

Плагін не малює для цього жодного інтерфейсу — це робить плеєр самої Astra.

## Що робить Astra, щоб цього не робив плагін

Усе довкола плагіна бере на себе медіахаб демона:

- **Зіставлення.** Коли сервіс грає на цьому комп'ютері, в ОС зазвичай є
  медіасесія того самого відтворення (застосунок Spotify, вкладка браузера). Хаб
  поєднує їх, і одна пісня — одна сесія: сесія ОС отримує ваше вподобання й
  чергу, нічого не показується двічі. ОС лишається джерелом істини про те, що
  ЧУТНО: ваші назва, обкладинка й позиція її не перезаписують.
- **Віддалені сесії.** Сесія, яку ви позначаєте як таку, що грає НЕ на цьому
  пристрої (телефон, колонка), показується окремо, з позначкою «віддалена». Вона
  ніколи не видається за «цей комп'ютер» — острів її не показує.
- **Маршрутизація.** Для поєднаної сесії play/pause/next/seek ідуть через ОС —
  так працює будь-який застосунок; вподобання, його скасування, перемішування,
  повтор, гучність, черга й запуск ідуть до вас.
- **Межі й безпека.** Обкладинки завантажує демон (лише https і ніколи — мережа
  цього комп'ютера); посилання — https або відома схема застосунку; рядки та
  списки обрізаються; усе, що модель читає від вас, позначається як текст із
  недовіреного джерела.

Тож плагін лише повідомляє, що грає кожен сервіс, і виконує по одній дії за раз.

## Створіть провайдер

<!-- doctest: cli -->
```bash
astra-plugin new my-music --lang python --template blank --capabilities music_provider --output ./my-music
```

`--lang` може бути й `rust`, і `typescript`. Окремого музичного шаблону немає:
можливість приходить через `--capabilities`, а `music_control` у заготовці
відповідає `not_configured`, доки ви його не реалізуєте. `astra-plugin test`
перевіряє хуки із сесією та елементом, яких жоден плагін не повідомляє. На ключ
сесії, який ваш плагін не публікував, SDK відповідає `not_found` ще до вашого
хука, тож проба не може поставити на паузу чи вподобати щось на вашому власному
плеєрі. Виняток — `MusicSearch`: він надсилає справжній запит, і плагін із
виконаним входом відповість зі справжнього сервісу (пошук нічого не змінює).

Вкажіть `min_astra_version`: `[capabilities]` — закритий набір, і Astra, старша
за ту, де з'явився `music_provider`, відхилить увесь маніфест.

## Звіт: публікуйте весь набір цілком

Звіт — це push. Кожен SDK тримає публікатор — `self.music` у Python і
TypeScript, `MusicPublisher`, який ви повертаєте з `music_publisher`, у Rust — і
обслуговує з нього довготривалий потік `MusicSubscribe` демона: останній знімок
одразу, знову з кожною публікацією й кожні `music_snapshot_heartbeat_secs` (15 с),
щоб помітити плагін, що замовк. Знімку, старшому за `music_session_stale_secs`
(45 с), демон більше не вірить.

**Кожна публікація — це ВЕСЬ набір.** Сесія, яку ви не включили, закінчилася.

<!-- doctest: illustrative reason="needs a running service account; shows the publish call shape only" -->
```python
self.music.publish(
    [MusicService("spotify", "Spotify", can_search=True, can_play=True)],
    [MusicSession(
        session_key="spotify",
        service_id="spotify",
        this_device=True,
        device_name="DESKTOP-1",
        exclusive_app_hints=["spotify", "spotify.exe"],
        status="playing",
        title="Believer",
        artist="Imagine Dragons",
        artwork_url="https://i.scdn.co/image/…",
        position_seconds=42.0,
        duration_seconds=204.0,
        liked=True,
        controls=["play", "pause", "next", "previous", "seek", "like", "unlike", "queue", "play_into"],
    )],
)
```

Поля, від яких залежить зіставлення:

| Поле | Значення |
|---|---|
| `this_device` | звук може йти з ЦЬОГО комп'ютера. Лише така сесія може поєднатися з сесією ОС |
| `exclusive_app_hints` | ідентифікатори сесій ОС застосунку, що не грає нічого, крім цього сервісу, — виконуваний файл Spotify, ім'я MPRIS-плеєра. Збігу достатньо |
| `shared_app_hints` | хости багатьох речей водночас, як-от браузери. Зв'язок виникає, лише якщо збігаються і назва, і виконавець |

Підказка порівнюється без урахування регістру з ідентифікатором сесії ОС, його
останнім сегментом шляху чи AppUserModelId, цим сегментом без `.exe` та ім'ям
MPRIS-плеєра — тож `spotify` однаково називає `C:\…\Spotify.exe`,
`SpotifyAB.SpotifyMusic_zpdnekdrzrea0!Spotify` і `org.mpris.MediaPlayer2.spotify`.

`controls` перелічує дієслова сесії з фіксованого списку; усе інше демон
відкидає: `play`, `pause`, `next`,
`previous`, `seek`, `like`, `unlike`, `shuffle`, `repeat`, `volume`, `queue` (ви
відповідаєте на `MusicGetQueue`) і `play_into` (ви відповідаєте на `MusicPlay`).

## Відповіді: чотири хуки

| Хук | Обов'язковість | Що робить |
|---|---|---|
| `MusicControl` | обов'язковий | одна дія над однією сесією; `value` містить секунди для `seek`, `0`–`100` для `volume`, `on`/`off` для `shuffle`, `off`/`track`/`context` для `repeat` |
| `MusicGetQueue` | необов'язковий | черга сесії довкола елемента, що грає, з `current_index` |
| `MusicSearch` | необов'язковий | пошук у каталозі; `item_ref` кожного елемента — ваш власний і повертається в `MusicPlay` |
| `MusicPlay` | необов'язковий | запустити елемент або перший збіг за словами — `mode` буває `now`, `next` або `end` |

**Відмова, яку ви маєте на увазі, — це відповідь**, а не помилка: користувач не
ввійшов, сервіс вимагає підписку, ніде нічого не грає. Киньте або поверніть
відмову SDK — `MusicRefusal` в усіх трьох — з одним із кодів `not_supported`,
`not_found`, `no_active_device`, `auth`, `premium_required`, `rate_limited`,
`unavailable`, `not_configured`. Демон покаже її людині її мовою. Будь-яка інша
помилка означає, що плагін зламаний.

<!-- doctest: illustrative reason="the service calls are placeholders; shows the refusal shape only" -->
```python
async def music_control(self, request):
    if not self.signed_in:
        raise MusicRefusal(MusicErrorCode.NOT_CONFIGURED, "Connect Spotify in the plugin's settings")
    device = self.devices.get(request.session_key)  # act on THE session named
    if device is None:
        raise MusicRefusal(MusicErrorCode.NOT_FOUND, "That player has gone")
    await device.do(request.action, request.value)
```

## Де легко помилитися

- **Повідомляйте позицію такою, як прочитали, без екстраполяції вперед.** Демон
  сам екстраполює сесію, що грає, від моменту, коли ця позиція прийшла вперше:
  сесія, надіслана повторно без змін (так робить heartbeat), зберігає позначку, а
  нова позиція її оновлює.
- **Тримайте ключі сесій стабільними** (`[A-Za-z0-9._-]{1,64}`), доки це те саме
  відтворення; новий ключ — нова сесія.
- **Не оголошуйте вкладку браузера ексклюзивною.** Браузер грає багато чого;
  така підказка повісить ваше вподобання на чиєсь відео.
- **Не зберігайте токени входу в `[config]`.** Astra зберігає конфіг як звичайний
  JSON і показує його на сторінці плагінів; використовуйте keyring ОС.
