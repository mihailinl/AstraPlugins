# Сайдлоадинг — інструмент розробника

> Переклад. Джерело істини — [docs/en](../../en/5-publish/sideload.md); за розбіжності відповідає англійська версія.

> **Це не те, як встановлюються плагіни.** Сайдлоадинг вказує Astra на
> каталог з вихідним кодом на вашому диску і запускає його, непідписаним, як
> нативний процес з правами вашого повного облікового запису. Він існує,
> щоб ви могли розробляти плагін. Він за явним увімкненням, і це увімкнення
> знижує планку для **кожного** плагіна на машині, а не тільки вашого.
>
> Користувачі встановлюють зсередини Astra. Автори публікують через
> [`init-ci` і тег](release-with-ci.md), а потім
> [потрапляють до каталогу один раз](get-listed.md) —
> [весь шлях на одній сторінці](../publishing.md).
>
> Сказати комусь клонувати ваш репозиторій і сайдлоаднути його — це не
> публікація. Це прохання запустити непідписаний код від свого імені, і
> воно досягає рівно тих людей, з якими ви можете поговорити.

Ніколи не сайдлоадьте плагін, який ви не писали і не перевіряли. Якщо
хтось надсилає вам каталог і інструкцію увімкнути режим розробника, він
просить вас запустити його код від вашого імені.

## Як увімкнути

Сайдлоадинг відхиляється, якщо `safety.allow_unsigned_plugins` не `true`.
Демон каже про це рівно так:

<!-- doctest: illustrative reason="the daemon's refusal, quoted from astra-daemon/src/plugins/manager.rs; reproducing it needs a running Astra with the setting off" -->
```
Sideloading is disabled. It runs an unsigned local plugin as native code with
your full privileges. Turn on Settings -> Privacy -> "Allow unsigned plugins"
(`safety.allow_unsigned_plugins`) to sideload (local plugin development only).
```

а CLI перетворює це на ту саму інструкцію з рішенням на окремому рядку
(`astra-plugin-cli/src/daemon.rs`). Два повідомлення називають різні
розділи налаштувань — демон каже Privacy, CLI каже Safety. **Ключ
налаштування — `safety.allow_unsigned_plugins`**, і саме його треба шукати.

## Як використовувати

Одна команда, з [CLI](../install-cli.md):

<!-- doctest: cli -->
```bash
astra-plugin dev
astra-plugin dev . --daemon-addr 127.0.0.1:32000
```

`dev` робить чотири речі по порядку і зупиняється на першому ж збої:

1. `astra-plugin check --strict` — вона не передасть демону маніфест, який
   уже неправильний;
2. збирає;
3. передає **каталог** демону через `SideloadPlugin`, який запускає процес,
   випускає його токен авторизації і з цього моменту володіє його життєвим
   циклом;
4. стежить за змінами, пересобирає, зупиняє/запускає плагін і хвостом
   читає його вивід.

<!-- doctest: output from="astra-plugin dev . with no Astra running" unrun="needs a machine with no Astra daemon listening, which a CI runner cannot promise either way" -->
```
Dev mode: plugin 'dice-roller'
  Directory: /tmp/dice-roller
Checking plugin at /tmp/dice-roller...
  OK: plugin 'dice-roller' v0.1.0 is valid (0 warning(s), 2 note(s), capabilities: tools)
  Running cargo build --release...
    Finished `release` profile [optimized] target(s) in 2.48s
Error: Could not read /home/you/.config/astra/daemon.token. Astra does not look
like it is running — start the app first.
```

**Демон володіє процесом, і це не стилістичне рішення.** Плагін
автентифікується в `PluginHostService` токеном, який демон видає, коли
запускає процес, і демон відхиляє будь-який `Register`, що не несе токена,
який він сам видав. У плагіна, запущеного CLI, немає способу його
отримати — самозапускний цикл розробки, який це замінило, запускав процес,
що ні з ким не спілкувався.

`--standalone` зберігає ту стару поведінку для випадків, де вона все ще
корисна (перевірити, що бінарник запускається, покрутити його вручну), і
одразу каже, що таким чином плагін не може зареєструватися в Astra.

`dev --json` відхиляється навмисно: `--json` обіцяє один документ на
запуск, а `dev` ніколи не завершується. `astra-plugin check --json`,
`astra-plugin test --json` і `astra-plugin logs --json` — це
машинозчитувані половини того, що вона робить.

## Чого коштує сайдлоадинг, точно

| | |
|---|---|
| **Підпис** | жодного. Ніщо не поручається за код |
| **Права** | ваш повний обліковий запис користувача. Пісочниці немає — [фази 7 не існує](../1-orientation/security.md) |
| **Радіус ураження перемикача** | `allow_unsigned_plugins` застосовується до кожного плагіна на машині, включно з непідписаними файлами, які ви імпортуєте пізніше |
| **Автозапуск** | **ніколи.** Режим розробника потрібен у момент завантаження, і перезапуск залишає сайдлоаднутий плагін зупиненим, поки ви не запустите його знову |
| **Стеля дозволів** | **жодної** — див. нижче |
| **Походження, що показується користувачу** | рівень `sideloaded` — «завантажено з папки» — у панелі походження |

### Чому тут немає стелі дозволів

У [локально імпортованого `.astraplugin`](local-install.md) чотири дозволи
відхиляються безумовно. У сайдлоаднутого **каталогу з вихідним кодом** —
ні, і цей виняток навмисний, а не недогляд: це цикл розробки для
UI-плагінів, і `dom_access` — це рівно те, що потрібно `companion`, `doom`
і `bad-apple`. Обмеження стелею рівня 3 зробило б їх нерозроблюваними.

Компроміс у тому, що рівень 3 закритий за явним налаштуванням, ніколи не
запускається автоматично і є каталогом, на який ви вказали самі — три
факти, які рівень 2 (файл, що прийшов звідкись) заявити не може.

План також просить постійний, невидалюваний бейдж «РОЗРОБНИК —
неверифікований код з локального каталогу» на картці плагіна і на рамці
вікна щоразу, коли активний `dom_access`. **Цього бейджа сьогодні немає в
інтерфейсі**, і ця сторінка не стверджує протилежного.

## Що не працює і не працюватиме

**Ручне створення маркера `sideload.json` у каталозі плагінів.** Демон
відхиляє маркер, про який у нього немає запису авторизації:

<!-- doctest: illustrative reason="a daemon log line, quoted from astra-daemon/src/plugins/manager.rs; it is emitted on a machine with a planted marker" -->
```
Refusing sideload marker in <path>: this daemon never authorised a sideload of
'<id>' from <source> (no matching record in <registry path>). A marker file
alone does not authorise running unsigned native code.
```

Старіші інструкції казали авторам підкласти маркер у
`~/.config/astra/astra/plugins` — шлях, якого не існує, поверх механізму,
що більше не працює, без згадки передумови `allow_unsigned_plugins`. Їх
було видалено, а не виправлено. Заміна — один рядок: `astra-plugin dev`.

## Коли ви закінчили розробку

Ніщо в цьому шляху не виробляє те, що може встановити інша людина. Щоб
випустити реліз:

1. [`astra-plugin init-ci`](release-with-ci.md), потім тег — CI збирає й
   засвідчує його;
2. [`astra-plugin publish`](get-listed.md) — один раз, назавжди;
3. користувачі встановлюють його зсередини Astra, із закріпленим
   дайджестом.

Вимкнути `allow_unsigned_plugins` назад, коли ви не розробляєте, вартий цих
двох кліків.
