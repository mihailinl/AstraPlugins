# Reference

Two tiers, and the difference matters.

## Generated — cannot drift

These are produced by [`tools/docgen`](../../../tools/docgen/) from the code
they describe, and CI runs `python3 tools/docgen/gen.py --check`: a checked-in
page that differs from a fresh run fails the build, with a diff. The CLI page is
generated by *running* `astra-plugin --help` rather than by parsing `main.rs`,
because a second parser for clap's derive macros is one more thing that can
silently disagree with the tool.

They live one directory up, in [`../reference/`](../reference/), which is where
the generator writes them.

| Page | Generated from |
|---|---|
| [`plugin.toml`](../reference/manifest.md) | `astra-plugin-manifest` — the crate the daemon parses manifests with |
| [CLI](../reference/cli.md) | the `clap` definitions, by running the binary |
| [Protocol](../reference/protocol.md) | [`proto/plugin.proto`](../../../proto/plugin.proto) |
| [Errors](../reference/errors.md) | the error taxonomy in all three SDKs |
| [Hook parity](../reference/parity.md) | [`spec/hooks.yaml`](../../../spec/hooks.yaml) — 35 hooks, 3 SDKs |

Per-SDK hook tables, rendered from the same spec:
[Rust](../hooks/rust.md) · [Python](../hooks/python.md) ·
[TypeScript](../hooks/typescript.md).

## Written — reviewed by a person

Three pages describe things no generator can read off a type: what a permission
*means* to the user who is asked to grant it, how the three different things
called "config" fit together, and which process turns a plugin's string into the
sentence a user reads.

| Page | |
|---|---|
| [Permissions](permissions.md) | Each id, what it grants, and how to write a `reason` |
| [Config and settings fields](config-fields.md) | `[config]`, typed settings, and the TTS/STT field hooks |
| [Localisation](localisation.md) | `locales/<code>.json`, the `$key` marker, and where the English gate fires |

Every code sample on both is executed in CI by
[`docs/tools/doctest.py`](../../tools/doctest.py).
