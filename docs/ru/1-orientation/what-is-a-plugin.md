# Что такое плагин

Плагин — это **отдельная программа**, которую запускает демон Astra и которая
общается с ним по gRPC на localhost. Это не библиотека, она не загружается в
адресное пространство Astra и не является скриптом, который Astra
интерпретирует. Astra запускает её так же, как это сделал бы шелл — с
аргументами в командной строке, — и останавливает, попросив завершиться, а если
не завершилась, убивает группу процессов.

Из одного этого факта следует почти всё остальное:

- **Писать можно на чём угодно**, что говорит по gRPC. Здесь есть три SDK —
  Rust, Python, TypeScript — и они в [полном паритете](../../en/reference/parity.md):
  все 35 хуков во всех трёх.
- **У плагина ваши права, не меньше.** См. [модель безопасности](security.md).
- **Свои ошибки он переживает плохо, а ошибки Astra — никак.** Паника внутри
  обработчика перехватывается и возвращается как ошибка, а не убивает процесс
  (`astra-plugin-sdk/src/panics.rs`); падение всего процесса демон замечает
  проверкой здоровья в течение 15 секунд.

## Два направления

Всё, что делает плагин, — это одно из двух, и это две разные системы с разными
именами в `plugin.toml`.

| | Направление | Секция манифеста | Отвечает на вопрос |
|---|---|---|---|
| **Возможности** | демон → плагин | `[capabilities]` | Что плагин реализует и что Astra может у него *вызвать* |
| **Разрешения** | плагин → демон | `[permissions]` | Какие host-RPC плагин может вызывать *наружу* |

Раньше это было одно слово на два понятия, и означало оно первое — именно так
`dom_access`, самая опасная вещь в системе, стала тем, что плагин выдавал сам
себе простым объявлением. Теперь это два слова. Объявление
`[capabilities] event_handlers = true` не даёт подписаться на события; даёт
`[permissions] subscribe_events`, и только после согласия пользователя.

`[permissions]` работает **по принципу «запрещено по умолчанию»**: без секции
вообще плагин может вызвать `Register`, `PluginLog`, `GetPluginSelfConfig` и
`GetDaemonInfo` — и больше ничего
([`spec/permissions.md` §2](../../en/spec/permissions.md)).

## Десять возможностей

Каждый ключ — булев, по умолчанию `false`, и обязывает обслуживать некоторые
хуки. В правой колонке — *обязательные*; необязательные есть в
[таблице паритета](../../en/reference/parity.md).

| Ключ `[capabilities]` | Плагин становится | Хуки, которые обязаны быть |
|---|---|---|
| `tools` | набором функций, которые может вызвать модель | `ListTools`, `CallTool` |
| `tts` | синтезатором речи в настройках голоса | `TtsSynthesize`, `TtsListVoices` |
| `stt` | распознавателем речи | `SttProcess`, `SttGetLanguages` |
| `ai_provider` | бэкендом модели | `AiComplete` |
| `actions` | шагами в редакторе команд | `ExecuteAction`, `GetPluginActionTypes` |
| `triggers` | типами триггеров, на которые подписываются команды | `GetPluginTriggerTypes`, `FireTrigger` |
| `ui_contributions` | панелями, страницами и оверлеями в окне Astra | `GetUiContributions` |
| `event_handlers` | подписчиком на события демона | `SubscribeEvents` |
| `client` | собственным чат-клиентом | `SendChatMessage` |
| `dom_access` | кодом, работающим внутри окна Astra | никаких — это решение о рендеринге, а не хук |

Источник: [`reference/manifest.md`](../../en/reference/manifest.md),
сгенерировано из того крейта, которым демон разбирает ваш манифест. `ui_panels`
не возможность и никогда ею не была — три опубликованных примера объявляли её,
serde молча выбрасывал неизвестный ключ, и единственным симптомом было
сообщение `astra-plugin check` о том, что возможностей нет вообще. Именно
поэтому `[capabilities]` отвергает неизвестные ключи.

## Как выглядит манифест

Самый маленький осмысленный — плагин с инструментами, без разрешений и без
всего остального:

<!-- doctest: toml-manifest -->
```toml
[plugin]
id = "dice-roller"
name = "Dice Roller"
version = "0.1.0"
description = "Roll dice from chat."
author = "You"
license = "MIT"

[entry]
command = "target/release/dice_roller"

[capabilities]
tools = true
```

Плагин, который поджигает триггер, обязан попросить разрешение, а `reason` —
это то, что прочитает пользователь, когда Astra спросит его согласия:

<!-- doctest: toml-manifest -->
```toml
[plugin]
id = "dice-roller"
name = "Dice Roller"
version = "0.1.0"
description = "Roll dice, and fire a trigger when one comes up."
author = "You"
license = "MIT"
homepage = "https://github.com/you/dice-roller"

[entry]
command = "target/release/dice_roller"

[capabilities]
tools = true
triggers = true

[permissions]
fire_trigger = { reason = "Fires the trigger you configure when a roll completes" }
```

Все секции и ключи: [`reference/manifest.md`](../../en/reference/manifest.md).

## Чего плагин не может

- **Не может выдать себе разрешение — после установки.** Блок `[permissions]` —
  это просьба. Для плагина, установленного из каталога или импортированного
  файлом, выданный набор вычисляет демон исходя из происхождения плагина и
  хранит там, куда плагин не может писать: манифест лежит в собственном каталоге
  плагина, а его плагин править может. **Сайдлоаженный плагин — исключение**: на
  этом уровне манифест *и есть* запись согласия, потолка нет, и плагин может
  расширить свои права правкой собственного файла. См.
  [модель безопасности](security.md).
- **Не может обратиться к `ChatService` Astra напрямую.** Сессионный токен,
  который плагин получает при регистрации, ограничен `PluginHostService`. Запуск
  хода ИИ идёт через `SendChatMessage`, а он закрыт разрешением
  `send_chat_message` — из высокорисковых.
- **Не может полагаться на неподключённый хук.** Хук может существовать в proto
  и во всех трёх SDK, а вызывать его демону негде: сегодня такой —
  `TtsSynthesizeStream`. Реализовать его бесплатно; рассчитывать на вызов —
  нельзя, пока [таблица паритета](../../en/reference/parity.md) не скажет `live`.
- **Не может быть установлен на платформу, под которую нет бандла.** См.
  [платформы](platforms.md).
