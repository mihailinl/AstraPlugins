# Документация по плагинам Astra

> **Английская версия — основная.** Эти страницы переведены с неё и охватывают
> только написанные вручную разделы: ориентация, руководство, публикация и
> эксплуатация. Справочник (`plugin.toml`, CLI, протокол, ошибки, таблица
> хуков), гайды по SDK и спецификации существуют только на английском, потому
> что они генерируются из кода и сверяются с ним в CI — перевод отставал бы от
> них молча. См. [docs/en](../en/README.md).

Плагин — это отдельная программа, которую Astra запускает и с которой общается
по gRPC. Она может дать модели инструменты, реализовать синтез или распознавание
речи, добавить шаги и триггеры в редактор команд, добавить свой интерфейс или
быть отдельным чат-клиентом.

Здесь два пути, и всё на этой странице относится к одному из них.

## Опубликовать плагин

Канонический путь — и единственный, который видят пользователи:

1. [Релиз через CI](5-publish/release-with-ci.md) — `astra-plugin init-ci`, затем тег. GitHub собирает бандл и выдаёт на него аттестацию сборки.
2. [Попасть в каталог](5-publish/get-listed.md) — одна заявка, один раз навсегда. Дальше релизы идут без участия человека.
3. Пользователи ставят плагин из самой Astra, а артефакт закреплён по дайджесту.

Есть ещё два способа попасть на машину. Оба — для разработчиков, оба чего-то
стоят, и оба честно говорят чего:

- [Установка локального файла](5-publish/local-install.md) — `.astraplugin`, полученный со стороны. Четыре разрешения отклоняются наотрез.
- [Сайдлоад каталога с исходниками](5-publish/sideload.md) — цикл разработки. Требует режима разработчика и запускает неподписанный код с вашими полными правами.

Ещё: [версионирование и политика устаревания](../en/versioning.md) ·
[переход на 0.6](../en/migration-0.6.md) — на английском.

## Справочник — только на английском

Большая часть справочника **генерируется** из кода, который она описывает, и CI
падает, если зафиксированная страница отличается от свежей генерации. Поэтому
она не переводится: генератор не умеет переводить, а рукописная копия — это
второе определение интерфейса, и неправым всегда оказывается именно оно.

| Страница | Из чего сгенерирована |
|---|---|
| [`plugin.toml`](../en/reference/manifest.md) | `astra-plugin-manifest` — крейт, которым демон разбирает ваш манифест |
| [CLI](../en/reference/cli.md) | определения `clap`, через запуск `astra-plugin --help` |
| [Протокол](../en/reference/protocol.md) | `proto/plugin.proto` |
| [Ошибки](../en/reference/errors.md) | таксономия ошибок во всех трёх SDK |
| [Паритет хуков](../en/reference/parity.md) | `spec/hooks.yaml` — все 35 хуков в трёх SDK |
| [Разрешения](../en/3-reference/permissions.md) | написано вручную: каждое разрешение и как написать причину |
| [Поля настроек](../en/3-reference/config-fields.md) | написано вручную: `[config]` и хуки полей TTS/STT |

Нормативные спецификации — для тех, кто пишет верификатор или реестр, а не

## Две вещи, за которыми следит вся эта документация

**Плагины не изолированы.** Плагин — это нативный процесс, работающий от вашего
имени, с вашими файлами и вашей сетью. Подписи отвечают на вопрос *кто
опубликовал эти байты*; разрешения — *что демон сделает по просьбе плагина*. Ни
то, ни другое не отвечает, что процесс может сделать с вашей машиной. См.
[модель безопасности](1-orientation/security.md).

**Цепочка доверия описана, но пока не заякорена.** Корневые ключи, которые
сделали бы подписанный каталог проверяемым, не сгенерированы, поэтому обычная
сборка падает «в закрытое состояние» и считает любой каталог неподписанным. Это
записано в [`spec/registry-index.md` §0.1](../en/spec/registry-index.md) и
повторяется везде, где это важно, а не заминается.
