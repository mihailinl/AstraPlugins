# Плагины слова-активатора

> Перевод. Источник истины — [docs/en](../en/wakeword-plugins.md); при расхождении верна английская версия.

Плагин слова-активатора объявляет `wakeword = true` в разделе `[capabilities]`
своего `plugin.toml`. Astra показывает установленные плагины с этой возможностью
в разделе **Голос → Слово-активатор**. Выбор и его настройки исчезают, когда
плагин удаляют. Плагину не нужна отдельная страница или вклад в интерфейс.

## Создайте новый детектор

Возьмите текущий CLI и новый выходной каталог:

<!-- doctest: cli -->
```bash
astra-plugin new my-wakeword --lang rust --template blank --capabilities wakeword --output ./my-wakeword
```

`--lang` может быть и `python`, и `typescript`. Шаблона для слова-активатора пока
нет. Пустая заготовка Rust содержит посторонний инструмент `hello` и его тест:
замените и то, и другое. Оставьте `wakeword = true` единственной возможностью,
если плагин действительно не обслуживает что-то ещё. `astra-plugin check` найдёт
расхождение между манифестом и скомпилированным бинарником.

Демон отправляет три описанных ниже вызова через `CallFromUi`, даже плагину,
который объявляет только `wakeword`. Это повторное использование транспорта; оно
не требует ни `ui_contributions`, ни iframe, ни `push_to_ui`. Общие таблицы хуков
относят `CallFromUi` к интерфейсу, потому что изначально он для этого.

В Rust реализуйте хук SDK `handle_ui_call(&self, ctx: &PluginContext,
method: &str, params_json: &str) -> Result<String, ToolError>` или используйте
методы `#[ui_call]` (с `#[ui_call(name = "process-audio")]` и
`#[ui_call(name = "reset-audio")]` для имён с дефисом); каждому методу
`#[ui_call]` нужен doc-комментарий `///`, иначе макрос откажется его
компилировать. Поставьте `#[astra::plugin(capabilities = "wakeword")]` на блок
impl (заготовка выше уже это делает): иначе автоматический вывод из `#[ui_call]`
объявит `ui_contributions`, а это расходится с манифестом. Направляйте `status`,
`reset-audio` и `process-audio` в один экземпляр детектора, чей буфер кадров
сохраняется между вызовами. Возвращайте JSON-строки в формах ответа, показанных
ниже.
В Python используйте обработчики SDK `@ui_call`; в TypeScript —
`ui: { contributions: [], onCall: { ... } }` с тремя именами методов.
Эти обработчики не создают видимой страницы интерфейса.
Точка входа, доступ к конфигурации и жизненный цикл описаны в руководствах по
SDK для [Rust](4-sdk/rust.md), [Python](4-sdk/python.md) и
[TypeScript](4-sdk/typescript.md).

Свои настройки плагин передаёт через уже существующую JSON Schema в `[config]`.
Astra показывает эти поля в разделе «Голос», только пока выбран этот плагин, и
сохраняет их через `UpdatePluginConfig`. Поддерживаются строковые, числовые,
булевы свойства и перечисления. Строка с `"format": "password"` превращается в
поле пароля; `"format": "file"` (или `"x-astra-field-type": "file_picker"`)
предлагает выбор локального файла. `"x-astra-field-type": "slider"` и
`"textarea"` выбирают эти элементы управления для числовых и строковых свойств.
Настроенный путь читает сам плагин; формат модели ключевого слова Astra не
предписывает.

Протокол 1 использует для трёх методов аутентифицированный канал
запрос/ответ `CallFromUi`. Это внутренний вызов демона; ни iframe, ни страница
не создаются.

| Метод | JSON запроса | JSON ответа |
|---|---|---|
| `status` | `{}` | `{"ready": true}` или `{"ready": false, "message": "…"}` |
| `process-audio` | `{"pcm_base64": "…"}` | `{"detected": false}` или `{"detected": true}` |
| `reset-audio` | `{}` | `{}` |

`pcm_base64` содержит моно-PCM 16 кГц, знаковый, 16 бит, little-endian. Astra
отправляет по 100 мс (1600 отсчётов) за вызов. Если у детектора другая длина
кадра, плагин должен сохранять отсчёты между вызовами. `reset-audio` отбрасывает
это сохранённое аудио и промежуточное состояние распознавания в модели, когда
Astra сбрасывает шлюз активации. Декодируйте Base64, отвергайте испорченный PCM и
PCM нечётной длины, превращайте каждую пару байтов little-endian в `i16` и
подавайте отсчёты в детектор по порядку. Не считайте каждый блок в 100 мс
законченной фразой. У каждого вызова срок две секунды; аудиоцикл использует
ограниченную очередь и никогда не ждёт плагин.
`astra-plugin test` вызывает все три метода и проверяет форму их JSON-ответов,
включая блок аудио из одних нулей, пока плагин, возможно, не настроен. Этот тест
не проверяет, что выбранное ключевое слово распознаётся. Перед поставкой
загрузите рабочую модель и проверьте `status.ready = true`; проиграйте несколько
записей фразы-активатора через несколько вызовов по 100 мс; и проиграйте тишину,
фоновый шум и обычную речь как отрицательные случаи. Убедитесь, что `reset-audio`
сбрасывает недоговорённую фразу и что после сброса распознавание работает. Затем
установите плагин или сайдлоадните его, выберите в **Голос → Слово-активатор** и
убедитесь, что Astra начинает слушать и просыпается на фразу. Ненастроенная
модель должна сообщать `ready: false` с полезным сообщением.

Astra проверяет `status.ready`, прежде чем начать слушать. Если выбранного
плагина нет, он остановлен или не готов, прослушивание отказывает (fail closed),
а не превращается молча в непрерывную расшифровку. Выбор во время работы задаётся
через `voice.wake_word_mode = "plugin__<id>"`, где дефисы в ID плагина заменены
подчёркиваниями, как и в ID провайдеров у плагинов STT и TTS.
Сообщайте `ready: true`, только когда детектор и его настроенная модель могут
обрабатывать аудио; одного наличия пути к файлу недостаточно.
