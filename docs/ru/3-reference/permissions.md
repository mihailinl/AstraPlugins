# Разрешения

> Перевод. Источник истины — [docs/en](../../en/3-reference/permissions.md); при расхождении верна английская версия.

Что даёт каждый id из `[permissions]`, чего это стоит пользователю, и как
написать `reason`, который стоит читать.

Это страница для авторов. Нормативные правила — выдачи, потолки,
`permissions_hash`, точная семантика отказа — в
[`spec/permissions.md`](../spec/permissions.md). Сгенерированная таблица
того, какой RPC закрывает каждый id, — в
[`reference/manifest.md`](../reference/manifest.md) и
[`reference/parity.md`](../reference/parity.md), обе выведены из
`spec/hooks.yaml` и сверены с собственной таблицей демона правилом паритета
R6.

## Форма этого

`[capabilities]` говорит, что демон может вызвать **внутри** вашего плагина.
`[permissions]` говорит, какие RPC хоста ваш плагин может вызывать
**наружу**. Два вопроса, два раздела; возможность никогда не подразумевает
разрешение.

Три свойства, каждое из которых кого-нибудь да удивит:

1. **По умолчанию всё запрещено.** Отсутствие раздела `[permissions]`
   означает отсутствие RPC хоста сверх стартовой четвёрки.
2. **Объявить — значит попросить, а не получить.** Ваш манифест — это запрос.
   Выданный набор вычисляет демон, исходя из того, откуда плагин взялся, и
   для установленного или импортированного плагина хранит его там, куда
   плагин не может писать, — сам манифест лежит в каталоге плагина, который
   плагин может редактировать. **Сайдлоадинг это переворачивает**: для
   каталога с исходниками в режиме разработчика манифест *и есть* выдача,
   перечитываемая при каждой загрузке, без потолка. Именно это делает
   рабочим цикл разработки, и именно поэтому сайдлоадинг — инструмент
   разработчика, а не путь установки.
3. **Неизвестный id сохраняется и остаётся бездействующим.** Новые id
   выходят вместе с новыми версиями Astra, так что более старый демон
   сохраняет ключ, который не распознаёт, вместо того чтобы отклонить ваш
   манифест. Он ничего не даёт. `astra-plugin check` предупреждает — опечатку
   невозможно отличить от прямо совместимого id на этапе разбора, поэтому это
   предупреждение, а не ошибка, а `--strict` превращает его в неуспешный
   выход:

   <!-- doctest: output from="astra-plugin check --strict ." unrun="needs a plugin project in the working directory; re-run it in your own plugin" -->
   ```
     WARN: Unknown permission 'read_the_users_mail'. This Astra grants nothing for it. Valid: fire_trigger, subscribe_events, set_variable, send_chat_message, push_to_ui, set_theme_contribution, dom_access, client, read_ai_settings, speak, read_user_identity, receive_attachments, request_settings_change
     FAILED: 1 warning(s), and --strict treats warnings as errors
   ```

   Лист согласия на установку в Astra показывает тот же id под собственной
   меткой `permission.unrecognised`, так что он не теряется молча и на входе
   тоже.

## Четыре вызова, которым ничего не нужно

| RPC | Почему бесплатен |
|---|---|
| `Register` | Рукопожатие. Плагина ещё нет, чтобы у него были разрешения |
| `PluginLog` | Запись в собственный лог |
| `GetPluginSelfConfig` | Чтение собственных настроек |
| `GetDaemonInfo` | `version`, `state`, `grpc_port`, `language` — всё это уже было в ответе на регистрацию |

То, что `GetDaemonInfo` бесплатен, — решение, а не недосмотр: чекбокс,
который ничего не защищает, — это то, как пользователи привыкают их тикать
не глядя.

## Тринадцать id

| Id | Закрывает | Свой чекбокс | Отклоняется для локального импорта | Что позволяет |
|---|---|---|---|---|
| `fire_trigger` | `FireTrigger` | нет | нет | Запускать сохранённые автоматизации пользователя |
| `subscribe_events` | `SubscribeEvents` | нет | нет | Получать события демона — **берёт список разрешённых `types`** |
| `set_variable` | `SetVariable` | нет | нет | Писать в контекст переменных демона, в собственном пространстве имён |
| `send_chat_message` | `SendChatMessage` | **да** | **да** | Управлять ходом ИИ, как будто говорил сам пользователь |
| `push_to_ui` | `PushToUi` | **да** | нет | Отправлять событие в свои собственные панели |
| `set_theme_contribution` | `SetThemeContribution` | **да** | **да** | Переоформить всё приложение |
| `dom_access` | — (поверхность) | **да** | **да** | Выполнять свой код внутри окна Astra, с доступом к беседам и интерфейсу любого другого плагина |
| `client` | — (поверхность) | **да** | **да** | Быть фронтендом чата с собственной сессией |
| `read_ai_settings` | `GetAiSettings` | нет | нет | Читать провайдера, модель и адрес чата пользователя — но не ключ |
| `speak` | `Speak`, `StopSpeaking` | **да** | нет | Произносить свои слова вслух голосом Astra и останавливать их |
| `read_user_identity` | `GetUserIdentity` | нет | нет | Читать псевдонимы этой установки и аккаунта, в который выполнен вход, созданные только для твоего плагина |
| `receive_attachments` | — (доставка) | **да** | нет | Получать картинки, которые человек приложил, в инструменте, который их просит |
| `request_settings_change` | `RequestSettingsChange` | нет | нет | Попросить человека изменить настройку, которую может менять ассистент, на карточке, на которую он отвечает |

`dom_access` и `client` не закрывают ни один RPC, и в этом суть: это
**поверхности**. `dom_access` определяет, отрисовывается ли UI-вклад как
скрипт в окне Astra или как изолированный iframe; `client` — это потолок
того, чем плагин вообще может быть. Их отклоняют там, где выдаётся сама
поверхность, а не на шлюзе вызова. `receive_attachments` тоже не закрывает
ни один RPC, но с другой стороны: вызывать тут нечего. Оно решает, что Astra
*присылает* одному из твоих инструментов — [см. ниже](#получать-картинки-которые-приложил-человек).

`dom_access` дополнительно получает второй экран согласия. Если вы тянетесь
за ним, сначала прочтите [модель безопасности](../1-orientation/security.md)
и убедитесь, что `push_to_ui` в собственную панель не решит задачу.

## Аргументы

Два id принимают аргументы, и оба сужают то, что вы получаете.

<!-- doctest: toml-manifest -->
```toml
[plugin]
id = "meeting-notes"
name = "Meeting Notes"
version = "0.1.0"
license = "MIT"
author = "You"

[entry]
command = "bin/meeting_notes"

[capabilities]
tools = true
event_handlers = true

[permissions]
subscribe_events = { types = ["command_completed", "state_changed"], reason = "Notices when a recording command finishes so it can write the summary" }
set_variable = { scopes = ["plugin"], reason = "Stores the id of the note it just wrote so your commands can open it" }
fire_trigger = { reason = "Fires meeting_summarised when a summary is ready" }
```

- **`subscribe_events.types` — это список разрешённых, применяемый демоном**
  — а не фильтром, который отправляет ваш плагин. Без него каждый подписчик
  получал каждое событие, включая `speech_recognized`, которое несёт
  транскрипты пользователя. Пустой список не разрешает ничего.
- **`set_variable.scopes`** — это `"plugin"`, `"session"` или `"persistent"`.

## Чтение настроек ИИ пользователя

Плагин, который сам обращается к модели пользователя — собственный ассистент, суммаризатор, — должен знать, какого провайдера, какую модель и какой адрес выбрал пользователь. **Спрашивай об этом Astra; никогда не читай файлы Astra.** Объяви `read_ai_settings` и вызови `GetAiSettings` (`get_ai_settings()` в Rust и Python, `getAiSettings()` в TypeScript):

| Поле | Что это |
|---|---|
| `provider` | Идентификатор провайдера чата. Сохранённый пользователем адрес — это `openai_compatible`; собственный сервис Astra — `astra` |
| `model` | Идентификатор модели чата |
| `api_base_url` | Адрес. Userinfo, query и fragment убраны; путь отдаётся так, как его настроил человек (если ретранслятор кладёт токен в путь, ты его получишь). Для `astra` пусто: его адрес вызывать не тебе |
| `is_loopback` | Адрес находится на этой машине (`127.0.0.0/8`, `::1`, `localhost`) — локальная модель |

Ключа API здесь никогда нет, как нет и других сохранённых адресов пользователя, системного промпта и любой роли, кроме чата. Плагин, которому нужен ключ, просит его у пользователя в собственном `[config]` (пометь его секретным). Разрешение не высокорисковое и не отклоняется для локального импорта: это честный путь к этим сведениям, а цена выше, чем у чтения `settings.json`, толкала бы плагины не туда. Чтение собственных файлов Astra — то, что ищет ручная проверка при публикации. Astra старше этого вызова отвечает `UNIMPLEMENTED`.

## Говорить голосом Astra

Плагин, которому есть что объявить — таймер, закончившаяся сборка, пришедшее сообщение, — может попросить Astra сказать это. Объяви `speak` и вызови `Speak` (`speak(text)` в Rust и Python, `ctx.speak(text)` в TypeScript).

`speak` — **высокорисковое** разрешение: твои слова звучат голосом Astra, будто их сказала Astra, поэтому у него свой чекбокс согласия. Для локального импорта оно не отклоняется: объявить что-то вслух — обычное желание плагина, а решение — это чекбокс. Кроме выдачи, `Speak` нужны **аккаунт с доступом к Astra** и **включённая озвучка ответов** у человека; пока Astra заблокирована, вызов отклоняется.

Вызов длится столько же, сколько речь, и отвечает тем, что с ней стало:

| Исход | Что это значит | Что делать |
|---|---|---|
| `SPOKEN` | Её услышали | Ничего |
| `STOPPED` | Тишины попросили до того, как она закончилась: wake-word, выключенная озвучка ответов, «Стоп», твой собственный `StopSpeaking` | Ничего — **это не ошибка**. Не повторяй без просьбы |
| `NOT_SPOKEN` | Она не прозвучала; `error` (тот же `PluginError`, что несёт фрагмент чата) говорит почему | Смотри код ниже. Ничто отклонённое не ставится в очередь |

| `error.code` | Когда |
|---|---|
| `PLUGIN_ERROR_BAD_ARGUMENTS` | Текст пуст после удаления невидимых символов или длиннее **300 символов** (`speak_text_max_chars` в `spec/limits.yaml`). Более длинный текст отклоняется, а не обрезается |
| `PLUGIN_ERROR_RATE_LIMITED` | Твоё время речи исчерпано. Оно считается в символах — **450 сразу, затем 3 в секунду**, каждый вызов стоит не меньше 20, — и `retry_after_ms` говорит, когда снова появится место |
| `PLUGIN_ERROR_UNAVAILABLE` | Человек выключил голос Astra, Astra заблокирована, голоса нет или очередь речи не смогла его принять. Покажи текст вместо этого; не проси человека что-то менять |

Твои слова встают в очередь за твоими же прежними, на отдельной полосе, так что они никогда не перебивают ответ Astra. `StopSpeaking` останавливает всё, что ты просил сказать, — и звучащее, и ждущее в очереди, — и ничего больше; он разделяет разрешение `speak` и работает независимо от того, выполнен ли вход. Лимиты принадлежат демону: SDK экспортируют `SPEAK_TEXT_MAX_CHARS`, чтобы ты мог показать счётчик, и сами ничего не проверяют. Astra старше этого вызова отвечает `UNIMPLEMENTED`.

## Знать, кто пользуется Astra

Плагину, который ограничивает использование на человека или на машину — пробный период, квота, лицензия, — нужен стабильный id для каждого. **Спрашивай об этом Astra; никогда не читай серийный номер оборудования или файлы Astra.** Объяви `read_user_identity` и вызови `GetUserIdentity` (`get_user_identity()` в Rust и Python, `ctx.getUserIdentity()` в TypeScript):

| Поле | Что это |
|---|---|
| `install_id` | Эта установка Astra: та же после перезапусков и обновлений Astra и твоего плагина, другая на другой установке. Пусто, пока у Astra ещё нет ключа установки |
| `signed_in` | Человек вошёл в Astra |
| `authorized` | …и его аккаунту открыт доступ к Astra |
| `account_id` | Аккаунт, в который выполнен вход: один и тот же на каждом устройстве, где человек входит. Пусто, если не `authorized` |

Оба id — **псевдонимы, созданные только для твоего плагина**: другой плагин читает для того же человека и той же машины другие id, так что два плагина не могут связать по ним свои записи. Это верно для плагинов, честно пользующихся этим API: нативный код плагина может прочитать файлы Astra. Ни один не секрет, и ни один никогда не является собственным id аккаунта, именем или email человека либо серийным номером оборудования. Разрешение не высокорисковое и не отклоняется для локального импорта: это честная альтернатива серийному номеру машины, а высокая цена толкнула бы плагин обратно к нему. Astra старше этого вызова отвечает `UNIMPLEMENTED`.

**`auth_changed` сужен соответственно** (Astra, 2026-11-12). Плагин, которому выдано событие `auth_changed`, раньше получал собственный id аккаунта, отображаемое имя человека и его тариф. Теперь он получает `authenticated`, `authorized`, `timestamp` и `account_id` — тот же псевдоним, что отдаёт `GetUserIdentity`, и `""`, если у тебя нет `read_user_identity` или аккаунту не открыт доступ к Astra. `user_id` и `user_name` по-прежнему приходят, как `null`, а `subscription_tier` — как `""`, чтобы парсер, написанный под старую форму, продолжал разбирать; ни одно из них больше не несёт значения.

## Получать картинки, которые приложил человек

Инструмент, который работает с картинкой — прочитать чек, определить растение, описать фото, — может попросить картинки, которые человек приложил к сообщению, на которое сейчас отвечает Astra. **Ни один выпуск Astra пока этого не делает:** демон присылает их, только если собран с build feature `plugin-provider-slots`. Любая другая Astra игнорирует просьбу, и твой инструмент картинок не получает.

Нужны две вещи. Объяви `receive_attachments` в `[permissions]` и отметь каждый инструмент, которому нужны картинки; потом читай их в его обработчике:

| SDK | Отметить инструмент | Прочитать картинки |
|---|---|---|
| Rust | `#[tool(wants_attachments)]` или `ToolDef::new(…).with_attachments(true)` | `ctx.attachments()` |
| Python | `@tool("…", wants_attachments=True)` или `ToolDef(…, wants_attachments=True)` | `current_attachments()` |
| TypeScript | `wantsAttachments: true` в `tool({…})` или на `ToolDef` | `ctx.attachments` или `currentAttachments()` |

Каждая картинка несёт `mime_type` (`mimeType` в TypeScript), `data` — байты — и `filename`, голое имя, под которым её приложили, никогда не папку. Инструмент, который их не просил, читает пустой список, как и любой вызов без картинок.

Astra передаёт картинки вызову, только когда выполнено всё это:

- инструмент объявил `wants_attachments` в своём ответе на `ListTools`;
- у твоего плагина есть `receive_attachments`;
- вызов сделан, пока Astra отвечала на сообщение, которое человек отправил в беседе, — invocation вызова называет эту беседу. Никогда в report wake, в ИИ-шаге команды или в ходе субагента и никогда, пока Astra удерживает ход ради команды из Workshop, которую человек не одобрил.

Приходит только то, что было приложено к **этому одному сообщению**: никогда картинка из более ранней части беседы, никогда картинка, созданная инструментом, и никогда картинка, которую назвала модель. Не больше **4** (`image_input_max_images` в `spec/limits.yaml`) и 20 MiB в сумме, сохраняются самые новые, в том порядке, в каком их приложили; картинка, которую не удаётся прочитать, не отправляется никогда. Если какие-то не отправлены — их больше, чем помещается, или у твоего плагина нет выдачи, — об этом говорят **модели** после твоего результата; твой инструмент просто получает меньше или ничего.

Сейчас поле ввода чата Astra уменьшает каждую приложенную картинку не больше чем до 768 пикселей и перекодирует её в JPEG, сохраняя исходное имя файла, — именно это и получает твой инструмент. Ориентируйся на `mime_type`, а не на расширение в `filename`.

Один вызов может нести до 20 MiB картинок — больше, чем лимит приёма gRPC по умолчанию, 4 MiB. Capability-серверы трёх SDK принимают до 64 MiB (`plugin_max_message_bytes`); плагин, который обслуживает протокол без SDK, должен поднять лимит приёма своего сервера выше 4 MiB.

`receive_attachments` — **высокорисковое** разрешение: фотографии человека попадают в код, который не принадлежит Astra, поэтому у него свой чекбокс согласия. Для локального импорта оно не отклоняется — решение принимает чекбокс, как и для `speak`.

## Попросить человека изменить настройку

Плагин, у которого есть настоящая причина хотеть, чтобы одна из настроек Astra изменилась, — модель, под которую настроены его инструменты, подходящий ему голос, — **просит**, а человек решает на карточке. Никогда не пишите `settings.json` Astra сами и никогда не одалживайте для этого собственную сессию Astra: так вы меняете Astra человека у него за спиной, и ручная проверка при публикации ищет именно это. Объявите `request_settings_change` и вызовите `RequestSettingsChange` (`request_settings_change(changes, reason)` в Rust и Python, `ctx.requestSettingsChange(changes, reason)` в TypeScript). **Ни один релиз Astra пока на него не отвечает:** демон принимает запросы, только если собран с функцией сборки `plugin-requests`; любая другая Astra отвечает `REFUSED` с кодом `not_compiled`.

Каждое изменение — путь настройки через точку и желаемое значение в виде JSON; SDK сериализуют значение за вас. Просить можно только о тех настройках, которые может менять сам ассистент, — голос, модель ИИ, язык; никогда режим разрешений, ключ или Tool Search, — и каждое значение проверяется точно так же, как собственное изменение ассистента. Карточка называет ваш плагин, показывает каждую настройку, какая она сейчас и какой станет, и ваш `reason` вашими словами. Меняются все или ни одна, и меняется ровно то, что показала карточка.

**Вызов длится, пока человек не ответит или карточка не истечёт** — это таймаут подтверждения Astra, не меньше 30 секунд, 120, если человек его не менял. SDK не ставят на него собственного дедлайна. Никогда не ждите его на пути, который должен ответить быстро, например в вызове инструмента, которого ждёт модель.

| Исход | Что это значит | Что делать |
|---|---|---|
| `APPLIED` | Человек разрешил; настройки теперь содержат то, о чём вы просили | Ничего |
| `UNCHANGED` | Они уже это содержали. Никого не спрашивали | Ничего |
| `DECLINED` | Человек сказал «нет» — сейчас или раньше, когда ваш плагин хотел изменить одну из этих настроек. Astra снова спросит о такой настройке, только когда она изменится другим путём, или после перезапуска | Продолжайте с тем, что у человека есть. **Не спрашивайте снова без повода** |
| `TIMED_OUT` | Никто не ответил, пока карточка не истекла (отсутствие открытого окна тоже сюда относится) | Спросите позже, когда человек будет рядом |
| `REFUSED` | Не спросили или не применили: `code` говорит почему, `refused_path` называет настройку, если дело в ней, а `error` — это `PluginError` | Смотрите код ниже |

| `code` | Когда |
|---|---|
| `not_compiled` | Эта Astra не принимает запросов: она собрана без функции `plugin-requests` |
| `locked` | Astra заблокирована паролем |
| `invalid` | Нет изменений, путь дважды, значение — не JSON, или больше, чем карточка может показать целиком |
| `too_many` | Больше **8** изменений (`settings_change_max_changes` в `spec/limits.yaml`) |
| `reason_too_long` | Причина длиннее **140 символов** (`settings_change_reason_max_chars`). Она показывается целиком, поэтому отклоняется, а не обрезается |
| `busy` | Один из ваших запросов уже ждёт человека: одна карточка на плагин за раз |
| `rate_limited` | **Два запроса разом, затем один в две минуты**; `error.retry_after_ms` говорит, когда снова будет место |
| `not_assistant_editable` | Путь, который ассистенту менять нельзя |
| `invalid_value`, `unknown_choice` | Значение, которое настройка не может содержать, или вариант, которого она не предлагает |
| `needs_api_key`, `needs_stt_provider`, `provider_unreachable` | Изменение оставило бы Astra без того, что ей нужно: ключа для этого провайдера ИИ, распознавателя речи, отвечающего провайдера |
| `stale` | Настройки изменились, пока карточка была открыта, так что разрешённое человеком — не то, что было бы записано. Ничего не записано |
| `stopped` | Полномочия вашего плагина закончились раньше — его остановили, отключили или отозвали, или аккаунт потерял доступ к Astra |
| `write_refused` | Настройки не удалось записать |

Текущие значения никогда не возвращаются: ваш плагин узнаёт только исход. Лимиты — дело демона: SDK экспортируют `SETTINGS_CHANGE_MAX_CHANGES` и `SETTINGS_CHANGE_REASON_MAX_CHARS` и сами не проверяют ни одного. Помимо разрешения, вызову нужен **аккаунт с доступом к Astra**; отсутствие разрешения или аккаунт без доступа к Astra — это неудачный вызов, как у любого вызова хоста, а не исход. Это не высокорисковое разрешение, и оно не отклоняется при локальном импорте: каждый запрос — карточка, на которую человек отвечает, так что согласие спрашивается каждый раз. Astra старше этого вызова отвечает `UNIMPLEMENTED`.

## Как написать reason

`reason` отрисовывается под собственной меткой Astra для разрешения,
визуально подчинённо, в кавычках, простым текстом, с ограничением в 140
символов, и всегда с префиксом *«The author says:»*. Метка принадлежит
Astra, на языке пользователя; reason — ваш. Вы не можете сформировать саму
метку, и это намеренно: формулировки фиксируются в поставке Astra и не
должны быть записываемыми через листинг.

Хороший reason:

- **называет фичу, которую узнаёт пользователь**, а не API — *«Запускает
  триггер on_dice_roll, который вы настроили»*, а не *«вызывает
  FireTrigger»*;
- **говорит когда**, если не всегда — *«только пока идёт запись»*;
- **не повторяет метку.** Astra уже её отрисовала;
- **не давит.** Никакой срочности, угроз, инструкций пользователю. Лист
  согласия — последнее место для исключения, и текст с bidi-переопределениями
  или соединителями нулевой ширины отклоняется там, где отображается
  дословно.

| Вместо | Пишите |
|---|---|
| `"needs fire_trigger"` | `"Fires the trigger you configure when a roll completes"` |
| `"required for the plugin to work"` | `"Reads command-completion events so it can log the run"` |
| `"full access to the UI"` | `"Draws the timer in the panel this plugin adds to the sidebar"` |
| `"REQUIRED! Do not disable!"` | — удалите разрешение или скажите, для чего оно |

Разрешение без правдоподобного reason — это разрешение, которое надо удалить
из манифеста. Автоматически это никто не проверяет; единственный заслон —
человек, читающий вашу заявку, и `astra-plugin check` скажет вам, когда вы
объявили разрешение, которое не нужно вашим возможностям.

## Что происходит, когда разрешения не хватает

Вызов возвращается с `permission_denied`, с сообщением, называющим
разрешение **и** откуда взялся выданный набор. В тесте это можно
инсценировать ровно так:

<!-- doctest: rust-plugin test=1 -->
```rust
use astra_plugin_sdk::prelude::*;

#[derive(Default)]
struct Notifier;

#[astra::plugin]
impl Notifier {
    /// Announce that something happened.
    #[tool]
    async fn announce(&self, ctx: &PluginContext) -> Result<String, ToolError> {
        // Handle the denial rather than propagating it: a tool that returns an
        // error the model cannot act on is worse than one that says what it did.
        match ctx.host().fire_trigger("announced", "{}").await {
            Ok(()) => Ok("announced".into()),
            // `{e:#}` and not `{e}`: the host call fails with a short outer
            // message and the useful half — the permission id and where the
            // granted set came from — is in the cause chain.
            Err(e) => Ok(format!("could not fire the trigger: {e:#}")),
        }
    }
}

astra::main!(Notifier::default());

#[cfg(test)]
mod tests {
    use super::*;
    use astra_plugin_sdk::testing::Harness;

    #[tokio::test]
    async fn a_missing_grant_is_reported_not_hidden() {
        let h = Harness::new(Notifier::default()).start().await.unwrap();
        h.host().deny("fire_trigger");

        let answer = h.call_tool("announce", json!({})).await.unwrap();
        assert!(answer.contains("fire_trigger"), "{answer}");
    }
}
```

`astra-plugin doctor` отвечает на этот же вопрос про манифест ещё до того,
как вы его хоть раз запустите:

<!-- doctest: output from="astra-plugin doctor ." unrun="reports this machine's toolchains, daemon and config paths, so its output differs on every machine" -->
```
  [ok  ] Why is a host call coming back `permission_denied`?
         [permissions] grants: none. Every declared capability has the host rpc it needs.
```

| Путь установки | Выдано |
|---|---|
| Из каталога, верифицирован | то, что запросил манифест, после согласия |
| Файл `.astraplugin`, импортированный вручную | манифест, **с потолком**: `send_chat_message`, `set_theme_contribution`, `dom_access`, `client` отклоняются безусловно |
| Сайдлоаднутый каталог с исходниками, режим разработчика включён | манифест, без потолка |
| `Untrusted` / `TamperDetected` / `Revoked` | ничего |
| Установлен до появления записей доверия | манифест, с потолком как у импортированного файла |

## Согласие, со стороны пользователя

Разрешения сгруппированы по риску. Семь высокорисковых получают каждое свой
чекбокс, и кнопка «Установить» остаётся неактивной, пока не отмечен каждый;
`dom_access` получает второй экран. Намеренно **нет ввода-для-подтверждения**:
это паттерн для необратимого уничтожения, а приучение пользователей печатать,
чтобы пройти его, уничтожает сигнал, который несёт чекбокс.

При обновлении: разрешения, не изменившиеся или сузившиеся, применяются
молча; разрешения, **расширившиеся**, ставят обновление в очередь без
установки и оставляют старую версию работающей, пока пользователь не
рассмотрит разницу. Отказ ничего не стоит.
