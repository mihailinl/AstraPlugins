# Производительность и лимиты

Каждое число на этой странице объявлено один раз, в файле, и сгенерировано туда,
где нужно. Ни одно не взято с потолка.

## Общие лимиты

[`spec/limits.yaml`](../../../spec/limits.yaml) — единственное место, где
записано число, которое обязано совпадать в демоне и в SDK. `node
tools/gen-limits.mjs` перегенерирует константы во всех трёх SDK, а
`const _: () = assert!(…)` рядом с копией демона не даст ему собраться, пока
демон не переедет следом. Породившая всё это ошибка: канал аудио для потокового
STT был 500 в демоне и 32 в Rust SDK, и это расхождение молча обрезало каждую
фразу до её первой части.

| Лимит | Значение | Что ограничивает |
|---|---|---|
| `plugin_start_timeout_secs` | **20** | От запуска до первой строки вывода плагина. Не уложились — демон считает запуск неудачным и убивает процесс |
| `plugin_stop_grace_secs` | **5** | От `Shutdown` до убийства группы процессов. Ваш собственный бюджет на завершение должен быть меньше, иначе демон убьёт вас раньше, чем отработает уборка |
| `stt_audio_channel_capacity` | **500** | Чанков в буфере между голосовым конвейером демона и вашим хуком `stt`, с обеих сторон. ~10 с аудио: худший случай стартового всплеска wake-word плюс живой звук, приходящий, пока медленный провайдер ещё считает |
| `max_extract_bytes` | **524 288 000** (500 МиБ) | Суммарный несжатый объём, который демон извлечёт из одного архива |
| `max_archive_entries` | **10 000** | Записей в одном архиве |

Последние два — защита от zip-бомб, и одновременно ограничение упаковки: бандл
сверх любого из них даёт неустанавливаемый плагин, поэтому CLI отказывается уже
на сборке, а не даёт узнать об этом на машине пользователя.

## `call_timeout_secs` — то, что задаёте вы

`plugin.call_timeout_secs` в манифесте — это сколько демон ждёт `CallTool` и
`ExecuteAction`, прежде чем сдаться. Если не задано, используется собственный
`PLUGIN_CALL_TIMEOUT` демона, который намеренно меньше «вечности».

**Плагин, за которым стоит долгоживущий агент, обязан его объявить.** Иначе
демон выбросит ваш результат, пока ваш подпроцесс продолжает работать:
пользователь видит ошибку, а машина продолжает считать.

<!-- doctest: toml-manifest -->
```toml
[plugin]
id = "coding-agent"
name = "Coding Agent"
version = "0.1.0"
license = "MIT"
author = "You"
# This plugin runs an agent that can legitimately take minutes.
call_timeout_secs = 180

[entry]
command = "bin/coding_agent"

[capabilities]
tools = true
```

Значение задаётся на плагин — так же, как таймаут MCP-сервера задаётся на
сервер. Ставьте столько, сколько нужно самому медленному законному вызову, а не
самое большое число, которое придумается: этот таймаут ещё и не даёт зависшему
плагину подвесить разговор.

## Бюджет запуска по языкам

Двадцать секунд — щедро, и два языка из трёх всё равно умудряются их потратить.

| | Типичный холодный старт | Что его съедает |
|---|---|---|
| Rust | миллисекунды | ничего |
| TypeScript | холодный старт Node | бандл — один файл, поэтому нет разрешения модулей по дереву |
| Python | интерпретатор + импорт `grpcio` | крупная зависимость, импортированная на уровне модуля |

Решение в обоих интерпретируемых случаях одно: **импортируйте лениво, внутри
хука, которому это нужно.** Модель, загруженная в `on_start`, — это модель,
которую пользователь ждёт до того, как плагин станет живым; модель, загруженная
при первом вызове, — та, которую он ждёт один раз.

`astra-plugin test` измеряет реальное число на вашей машине и печатает его
рядом с бюджетом:

<!-- doctest: output from="astra-plugin test . --no-build" -->
```
  [ok  ] the plugin says something before the daemon gives up: first line on stdout after 792.4µs
         (the daemon waits 20s, spec/limits.yaml plugin_start_timeout_secs)
  [ok  ] Shutdown is honoured within the grace period: the process exited 42.5ms after Shutdown
         (grace is 5s, spec/limits.yaml plugin_stop_grace_secs)
```

## Завершение в отведённое время

На `Shutdown` вы отвечаете и выходите. Через пять секунд группа процессов
убивается. Всё, что нужно сбросить на диск или закрыть у апстрима, сбрасывается
в этом окне или не сбрасывается вовсе.

При остановке всего демона отводится **гораздо меньше** времени, ограниченного
общим дедлайном выключения. Не считайте 5 секунд бюджетом, который можно
потратить, — считайте их потолком, до которого лучше не доходить.

## Проверки здоровья

`HealthCheck` выполняется каждые 15 секунд. Он не проходит через хелпер
необязательных хуков, поэтому **любая** ошибка — включая `UNIMPLEMENTED` —
помечает плагин мёртвым. Если переопределяете его, делайте дёшево и без
внешних зависимостей: проверка здоровья, ходящая в чужой сервис, превращает
аварию этого сервиса в смерть вашего плагина.

## Размер бандла

Максимума сверх лимитов извлечения нет, но две вещи стоит знать:

- Rust-бандл — это релизный бинарник со снятыми символами, обычно несколько
  мегабайт.
- TypeScript-бандл **не** несёт `node_modules` — `astra-plugin build` собирает
  один самодостаточный CommonJS-файл, и CI проверяет, что ничто в нём не тянется
  за модулем во время работы.

Воспроизводимая упаковка (`--reproducible`) фиксирует порядок записей, mtime и
уровень сжатия, поэтому две сборки из одних входов побайтово одинаковы. Релизный
workflow гоняет канарейку на каждом релизе — именно это делает чужую пересборку
осмысленной.
