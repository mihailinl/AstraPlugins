# Логи

Вывод плагина может оказаться в трёх местах, и понимание, где именно, экономит
час.

| | Куда попадает | Кто видит |
|---|---|---|
| `tracing::info!` / `logging.info(...)` (мост логирования SDK) | пересылается демону как `PluginLog` **и** в stderr | вы *и* пользователь, в панели логов Astra |
| `ctx.host().log_info(...)` — явный вызов | демону | вы и пользователь |
| `println!` / голый stderr | stdout/stderr процесса, которые захватывает демон | вы, через `astra-plugin logs` |

До появления моста это были два разных множества, и самые интересные строки —
паника, неудачный запрос, повтор — почти всегда лежали в том, которого
пользователь не видел.

## Как читать

<!-- doctest: cli -->
```bash
astra-plugin logs
astra-plugin logs dice-roller -f
astra-plugin logs dice-roller -n 500 --daemon-addr 127.0.0.1:32000
astra-plugin logs --json
```

Без id команда берёт `plugin.id` из манифеста в `--path`. Она работает для
**установленных** плагинов — случая, который `astra-plugin dev` не покрывает
вообще.

Демон держит **ограниченный кольцевой буфер на плагин**, а `GetPluginLogs` —
унарный вызов поверх него, поэтому `-f` это опрос каждые 750 мс, а «новые»
строки — это хвост, не продолжающий предыдущий. Перезапуск сбрасывает буфер.

Просить больше строк, чем в буфере, безвредно. `--json` печатает один документ и
выходит — это форма снимка; `-f` вместе с `--json` бессмысленны.

## Что SDK пересылает, а что нет

Слой `tracing`, который поднимает SDK, пересылает демону:

- **`INFO` и выше** по умолчанию. `ASTRA_PLUGIN_LOG_LEVEL` это меняет; `DEBUG`
  принадлежит `RUST_LOG` и stderr, потому что панель — для пользователя.
- **Не** транспортный стек — `h2`, `hyper`, `tonic`, `tower`, `rustls`,
  `tokio`. Отправка строки лога сама по себе RPC, а RPC, который логирует,
  порождает строку лога: без этого исключения один `WARN` от `h2` превращается в
  бесконечный цикл.
- **Не больше, чем влезает в очередь.** Канал ограничен, отправка
  неблокирующая, поэтому плагин в горячем цикле теряет строки, а не создаёт
  обратное давление на собственные обработчики через демон.

### Python

`install_logging_bridge()` направляет стандартный модуль `logging` тем же
путём. Используйте его вместо `print`: SDK переключает stdout на **построчную**
буферизацию, потому что супервизор демона читает stdout, чтобы понять, что
плагин жив, а блочная буферизация однажды приводила к тому, что супервизор убивал
здоровые плагины по таймауту запуска.

## Как включить трассировку самого CLI

`RUST_LOG` управляет `astra-plugin`. Он был задокументирован с 0.1 и не делал
ничего, пока не появился подписчик, — все события `tracing` от CLI и его
зависимостей уходили в никуда.

<!-- doctest: cli -->
```bash
RUST_LOG=astra_plugin=debug astra-plugin check
RUST_LOG=debug astra-plugin build
```

По умолчанию `warn`, и вывод идёт в **stderr** — пользовательский вывод CLI
живёт на stdout, и строка трассировки там испортила бы документ `--json`.

<!-- doctest: output from="astra-plugin doctor ." -->
```
  [ok  ] Why do I see no trace output from the CLI?
         RUST_LOG is unset, so only warnings and errors are printed.
         `RUST_LOG=astra_plugin=debug` turns on this CLI's own trace;
         `RUST_LOG=debug` turns on its dependencies' too.
```

## Файлы на диске

| | Linux | Windows |
|---|---|---|
| Логи демона | `~/.config/astra/logs/` | `%APPDATA%\astra\astra\config\logs\` |
| Каталог конфигурации, вычисленный CLI | спросите `astra-plugin doctor` | спросите `astra-plugin doctor` |

Файлы логов демона датированы (`daemon.log.2026-08-05`). Строки самого плагина
попадают туда через `PluginLog`, а сырые stdout/stderr — это то, что
`astra-plugin logs` читает из буфера демона в памяти; этот буфер не файл и
перезапуск демона не переживает.

Не гадайте, какой каталог использует эта машина, — спросите: `doctor` печатает
тот, который вычислил CLI, и если Astra с ним не согласна, то они вычислили
разные каталоги, и это уже сама по себе ошибка.

## Когда логов нет совсем

Процесс падает до того, как SDK поднимает логирование. Запустите его руками:

<!-- doctest: cli -->
```bash
astra-plugin dev --standalone
```

Так плагин запускается напрямую, а не через демон. Команда сразу говорит, чего
так сделать нельзя: плагин не сможет зарегистрироваться, потому что токен,
который требует `Register`, выпускает только демон.
