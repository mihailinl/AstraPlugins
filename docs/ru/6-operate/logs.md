# Логи

> Перевод. Источник истины — [docs/en](../../en/6-operate/logs.md); при расхождении верна английская версия.

Вывод плагина может оказаться в трёх местах, и знание, какое из них какое,
экономит час.

| | Куда уходит | Кто может это увидеть |
|---|---|---|
| `tracing::info!` / `logging.info(...)` (мост логирования SDK) | пересылается демону как `PluginLog`, **и** в stderr | вы *и* пользователь, в панели логов Astra |
| `ctx.host().log_info(...)` — явный вызов | демону | вы и пользователь |
| `println!` / голый stderr | stdout/stderr процесса, который захватывает демон | вы, через `astra-plugin logs` |

До появления моста это были два разных набора, и интересные строки —
паника, проваленный запрос, повтор — почти всегда оказывались в наборе,
который пользователь видеть не мог.

## Читаем их

<!-- doctest: cli -->
```bash
astra-plugin logs
astra-plugin logs dice-roller -f
astra-plugin logs dice-roller -n 500 --daemon-addr 127.0.0.1:32000
astra-plugin logs --json
```

Без id она читает `plugin.id` из манифеста в `--path`. Это работает для
**установленных** плагинов — случая, который `astra-plugin dev` вообще не
может обслужить.

Демон держит **ограниченный кольцевой буфер на плагин**, и `GetPluginLogs` —
унарный вызов над ним, так что `-f` — это опрос каждые 750 мс, а «новые»
строки — это суффикс этого хвоста, не продолжающий предыдущий. Перезапуск
сбрасывает буфер.

Запросить строк больше, чем держит буфер, безвредно. `--json` печатает один
документ и выходит — это форма снимка; `-f` и `--json` не образуют полезную
пару.

## Что пересылает SDK, а что нет

Слой `tracing`, который устанавливает SDK, пересылает демону:

- **`INFO` и выше**, по умолчанию. `ASTRA_PLUGIN_LOG_LEVEL` это меняет;
  `DEBUG` принадлежит `RUST_LOG` и stderr, потому что панель — для
  пользователя.
- **Не** транспортный стек — `h2`, `hyper`, `tonic`, `tower`, `rustls`,
  `tokio`. Отправка строки лога — это сама по себе RPC, а RPC, который
  логирует, производит строку лога: без этого исключения один `WARN` от
  `h2` становится бесконечным циклом.
- **Не больше, чем держит очередь.** Канал ограничен, а отправка
  неблокирующая, так что плагин в горячем цикле роняет строки, а не создаёт
  обратное давление своих обработчиков на демон.

### Python

`install_logging_bridge()` направляет стандартный модуль `logging` тем же
путём. Используйте его вместо `print`: SDK переключает stdout на
**построчную буферизацию**, потому что супервизор демона читает stdout,
чтобы понять, что плагин жив, а блочная буферизация вывода когда-то
приводила к тому, что супервизор убивал здоровые плагины по тайм-ауту
старта.

## Включаем собственную трассировку CLI

`RUST_LOG` управляет самой `astra-plugin`. Она документировалась с версии
0.1 и ничего не делала, пока не был установлен подписчик — каждое событие
`tracing`, которое испускали CLI и её зависимости, уходило в никуда.

<!-- doctest: cli -->
```bash
RUST_LOG=astra_plugin=debug astra-plugin check
RUST_LOG=debug astra-plugin build
```

По умолчанию — `warn`, и идёт в **stderr** — пользовательский вывод CLI на
stdout, и строка трассировки там повредила бы документ `--json`.

<!-- doctest: output from="astra-plugin doctor ." unrun="reports this machine's toolchains, daemon and config paths, so its output differs on every machine" -->
```
  [ok  ] Why do I see no trace output from the CLI?
         RUST_LOG is unset, so only warnings and errors are printed.
         `RUST_LOG=astra_plugin=debug` turns on this CLI's own trace;
         `RUST_LOG=debug` turns on its dependencies' too.
```

## Файлы на диске

| | Linux | Windows |
|---|---|---|
| Логи демона | `~/.config/astra/logs/` | `%APPDATA%\astra\astra\config\logs\` |
| Каталог конфигурации, который разрешила CLI | спросите `astra-plugin doctor` | спросите `astra-plugin doctor` |

Файлы логов демона датированы (`daemon.log.2026-08-05`). Собственные строки
плагина появляются там через `PluginLog`, а его сырой stdout/stderr — это
то, что `astra-plugin logs` читает из буфера демона в памяти — этот буфер
не файл, так что он не переживает перезапуск демона.

Спрашивайте, а не предполагайте, какой каталог использует эта машина:
`doctor` печатает тот, что разрешила CLI, и если Astra не согласна, значит
эти два разрешили разные каталоги — а это уже сам по себе баг.

## Когда логов вообще нет

Процесс падает до того, как SDK установит своё логирование. Запустите его
вручную:

<!-- doctest: cli -->
```bash
astra-plugin dev --standalone
```

Это запускает плагин напрямую, а не через демон. Она печатает, чего так
сделать нельзя — плагин не может зарегистрироваться, потому что только
демон может выпустить токен, который требует `Register`.
