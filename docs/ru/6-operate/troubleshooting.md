# Диагностика

Привязано к строкам, которые CLI и демон печатают на самом деле. Если ошибка у
вас перед глазами — ищите на этой странице её фрагмент.

## Начните отсюда

<!-- doctest: cli -->
```bash
astra-plugin doctor
```

Пятнадцать проверок, каждая сформулирована как вопрос, на который отвечает. Он
знает, какой CLI вы запустили, какой каталог конфигурации вычислил, доступен ли
демон, какие у вас тулчейны, разбирается ли манифест, существует ли точка входа,
покрывают ли разрешения ваши возможности, верен ли блок `[platform]` и закреплён
ли релизный workflow. У каждой неудачи есть строка `fix:`. В проекте, который
вы ещё не собирали, он завершится с ненулевым кодом на одной из них — `Will the
daemon find something to start? … does not exist` — и это правильно: бинарник
ещё ничем не создан.

## Проект не резолвит свой SDK

**`error: failed to select a version for the requirement astra-plugin-sdk = "^0.6"`**
**`ERROR: No matching distribution found for astra-plugin-sdk<0.6,>=0.5`**
**`error: No version matching "^0.5.0" found for specifier "astra-plugin-sdk" (but package exists)`**

Три языка, одна причина: `astra-plugin new` закрепляет ту версию SDK, которую
описывает эта документация, а в реестрах лежит предыдущая — crates.io 0.5.0,
PyPI 0.4.0, npm 0.4.0. На вашей машине ничего не сломано, и ни `doctor`, ни
`check` об этом не скажут: оба читают манифест, а пин лежит в файле сборки
конкретного языка. Направьте проект на копию SDK из этого репозитория — три
фрагмента лежат в [Быстром старте §2](../2-tutorial/getting-started.md). Не
ослабляйте границу вместо этого: 0.6 — первый релиз Rust SDK, чей `HostClient`
прикладывает `x-session-token`, так что старый SDK меняет эту ошибку на
`unauthenticated` на каждом host-вызове — см. раздел ниже.

## Плагин не запускается

**`Could not read /…/astra/daemon.token. Astra does not look like it is running — start the app first.`**
Ровно то, что написано. `dev`, `logs` и установка требуют работающей Astra;
`new`, `build`, `check`, `test`, `sign` и `publish` — нет. Если Astra *запущена*,
значит, она вычислила другой каталог конфигурации, чем CLI: сравните путь,
который печатает `doctor`, с тем, что Astra показывает в настройках.

**Демон убил процесс при запуске.** Бюджет — `plugin_start_timeout_secs` =
**20 с** до первой строки вывода. Python-плагин, импортирующий крупный ML-стек
на уровне модуля, может не уложиться; импортируйте лениво, внутри нужного хука.
`astra-plugin test` измеряет это и печатает число:

<!-- doctest: output from="astra-plugin test . --no-build" -->
```
  [ok  ] the plugin says something before the daemon gives up: first line on stdout after 792.4µs
         (the daemon waits 20s, spec/limits.yaml plugin_start_timeout_secs)
```

**Плагин стартует и сразу умирает.** Сначала посмотрите `astra-plugin logs -f`;
если там вообще пусто, процесс падает до того, как SDK поднимет логирование.
Запустите бинарник руками — `astra-plugin dev --standalone` делает именно это и
говорит, чего так проверить нельзя.

**Ошибки `HealthCheck` помечают плагин мёртвым.** Он выполняется каждые 15 с и
не проходит через хелпер необязательных хуков: *любая* ошибка, включая
`UNIMPLEMENTED`, означает «мёртв». Если вы переопределили `health_check`,
убедитесь, что он не может бросить исключение.

## Host-вызов возвращает `permission_denied`

Сообщение называет разрешение и то, откуда взялся выданный набор. Три причины по
убыванию вероятности:

1. **Вы его не объявили.** `[permissions]` запрещает всё по умолчанию.
   `[capabilities] event_handlers = true` не даёт `SubscribeEvents`; даёт
   `[permissions] subscribe_events`.
2. **Пользователь его не выдал** или путь установки его урезал. У
   [локально импортированного файла](../5-publish/local-install.md)
   `send_chat_message`, `set_theme_contribution`, `dom_access` и `client`
   отклоняются наотрез.
3. **Вы не вошли в аккаунт или приложение заблокировано.** Astra отвергает
   плагинные RPC в обоих состояниях, и CLI это говорит: *«Astra refuses plugin
   RPCs while signed out or locked — sign in and unlock the app, then try
   again.»*

`astra-plugin doctor` отвечает на пункт 1 ничего не запуская:

<!-- doctest: output from="astra-plugin doctor ." -->
```
  [ok  ] Why is a host call coming back `permission_denied`?
         [permissions] grants: none. Every declared capability has the host rpc it needs.
```

## Host-вызов возвращает `unauthenticated`

Каждый вызов `PluginHostService`, кроме `Register`, обязан нести сессионный
токен в `x-session-token`. Все три SDK его прикрепляют — **с 0.6 в Rust и с 0.5
в Python и TypeScript**. На более старом SDK так падает каждый host-вызов;
именно поэтому нижняя граница зависимости в шаблоне не опускается ниже.

`astra-plugin test` проверяет это end-to-end:

<!-- doctest: output from="astra-plugin test . --no-build" -->
```
  [ok  ] every host call carried the session token: no host call was refused for want of `x-session-token`
```

## Сайдлоад отклоняется

**`Sideloading is disabled.`** Выключен `safety.allow_unsigned_plugins`.
Прочитайте, [чего стоит его включить](../5-publish/sideload.md).

**`Refusing sideload marker in …: this daemon never authorised a sideload of …`**
Кто-то подложил `sideload.json` руками. Это перестало работать, когда демон стал
вести собственную запись выданных разрешений на сайдлоад. Используйте
`astra-plugin dev`.

## Установка отклонена

Любой провал проверки на пути из каталога — это **жёсткая блокировка без права
обхода**, и каждый называет, что именно из двух произошло.

| Что вы видите | Что это значит |
|---|---|
| Скачанный файл не совпадает с тем, что подписал реестр | `DIGEST_MISMATCH` — загрузка выброшена. Сообщите об этом |
| Astra не смогла проверить подпись каталога | `SIGNATURE_INVALID` — каталог отключается, а не откатывается на непроверенные данные |
| Обновление приходит из другого репозитория, чем установка | `IDENTITY_CHANGED` — обхода нет никогда. Закрепление снимает только удаление плагина |
| Плагин отозван | `REVOKED` — с текстом уведомления и удалением в один клик. Файлы никогда не удаляются молча |
| Этот бандл для другой платформы | `PLATFORM_UNSUPPORTED` |
| Плагину нужна более новая Astra | `PROTOCOL_UNSUPPORTED` |
| Сеть или неверные часы | Повторяемо, и сформулировано именно так. Это никогда не должно выглядеть как провал проверки |

**`nothing here vouches for these bytes`** на локальном файле: поставьте его со
страницы плагинов или прочитайте
[про установку локального файла](../5-publish/local-install.md), чего это стоит.

Сегодня цепочка доверия **не заякорена** — корневые ключи не сгенерированы, —
поэтому каталог считается неподписанным, а отзыв не применяется. См.
[`spec/registry-index.md` §0.1](../../en/spec/registry-index.md).

## Вызов инструмента падает так, что модель не может это починить

Используйте правильный код — именно его читает модель.

| Код | Когда |
|---|---|
| `BAD_ARGUMENTS` | Повтор с другими аргументами может сработать |
| `NOT_CONFIGURED` | Не хватает настройки — **и заполните `config_field`**, именно он превращает ошибку в ссылку на нужное поле |
| `UNAUTHORIZED` | Значение есть, и его отвергли. Это не то же, что `NOT_CONFIGURED` |
| `RATE_LIMITED` | С `retry_after_ms`, если апстрим его назвал |
| `UNAVAILABLE` / `TIMEOUT` | Временно. Такой же вызов позже может пройти |
| `INTERNAL` | Баг. Модели с этим делать нечего |

`UNIMPLEMENTED` — **не** ошибка: это «такого хука нет», и демон читает его
именно так. Вернуть его, потому что упал ваш TTS, — значит убедить демон, что
TTS у вас нет. Полная таксономия:
[`reference/errors.md`](../../en/reference/errors.md).

## `astra-plugin check` ругается

**`config.schema is not valid JSON`** или **`should have "type": "object" at
root`** — форма настроек генерируется из этой схемы.

**Неизвестный ключ в `[capabilities]` роняет весь манифест.** Это единственная
секция, где неизвестные ключи отвергаются, потому что каждый ключ — булев
opt-in, и опечатка иначе читалась бы ровно как `false`. Классика — `ui_panels`:
правильно `ui_contributions`, и из-за этого три опубликованных примера месяцами
не объявляли ничего.

**Неизвестный id в `[permissions]` сохраняется с предупреждением**, а не
отвергается: новые id приезжают с новыми Astra, а блок разрешений хешируется
побайтово тремя реализациями, поэтому выброшенный ключ заставил бы их разойтись
в том, что было подписано.

`astra-plugin check --fix` применяет то, что может доказать, и сообщает об
остальном.

## CLI не печатает ничего полезного

`RUST_LOG` теперь работает — он был задокументирован с 0.1 и не делал ничего,
пока не появился подписчик:

<!-- doctest: cli -->
```bash
RUST_LOG=astra_plugin=debug astra-plugin check
RUST_LOG=debug astra-plugin build
```

Трассировка идёт в **stderr**, чтобы `--json` на stdout оставался одним чистым
документом.

## Коды возврата

| | |
|---|---|
| `0` | успех |
| `1` | плагин или бандл неверен |
| `2` | CLI не смог выполнить проверку — нет файла, нет тулчейна |

Разделение существенно: релизный workflow, который считает «бандл плохой» и «я
не смог посмотреть» одним и тем же, однажды выпустит одно из двух.
