# Справочник `plugin.toml`

Каждый раздел, каждый ключ и всё, что что-либо отклоняет. Выведено из
[`astra-plugin-manifest`](../../../astra-plugin-cli/vendor/astra-plugin-manifest/src/manifest.rs)
— крейта, которым демон разбирает ваш манифест, завендоренного в этот
репозиторий и удерживаемого побайтово идентичным копии Astra через
`tools/check-manifest-crate.sh`. Второго определения манифеста, способного
разойтись с этой страницей, не существует.

Полный манифест плагина, разобранный из `plugin.toml`.

Намеренно **не** `deny_unknown_fields`: разделы добавляются с релизами —
`[permissions]` был последним — и более старый демон обязан пропускать
раздел, который не знает, а не отклонять плагин. `[capabilities]` —
исключение, и [`Capabilities`] объясняет почему.

## Разделы

| Раздел | Обязателен | Что объявляет |
|---|---|---|
| [`[plugin]`](#plugin) | **да** | Идентичность плагина и метаданные. |
| [`[entry]`](#entry) | **да** | Как запускать процесс плагина. |
| [`[capabilities]`](#capabilities) | нет | Что плагин **реализует**, демон→плагин. |
| [`[permissions]`](#permissions) | нет | Что плагин просит **вызывать**, плагин→демон — и это именно *просьба*. |
| [`[config]`](#config) | нет | JSON Schema для конфигурации плагина (авто-генерирует UI настроек). |
| [`[dependencies]`](#dependencies) | нет | Таблица строк, без собственной схемы. |
| [`[platform]`](#platform) | нет | Требования к платформе — `[platform]` в `plugin.toml`. |
| [`[build]`](#build) | нет | Метаданные сборки, добавляемые `astra-plugin build`. |
| [`[ui]`](#ui) | нет | Определения UI-вкладов, объявленные в plugin.toml. |

Раздел, который эта Astra не знает, — **сохраняется, а не отклоняется** —
разделы добавляются с релизами, и более старый демон должен уметь
пропустить один из них. `[capabilities]` — единственное исключение, и
причина ниже.

## `[plugin]`

Идентичность плагина и метаданные.

| Ключ | Тип | Обязателен | По умолчанию | Что это |
|---|---|---|---|---|
| `id` [†](#что-отклоняется) | строка | **да** | — | — |
| `name` [†](#что-отклоняется) | строка | **да** | — | — |
| `version` [†](#что-отклоняется) | строка | **да** | — | — |
| `description` | строка | нет | `""` | — |
| `author` | строка | нет | `""` | — |
| `license` | строка | нет | `""` | — |
| `homepage` | строка | нет | `""` | — |
| `min_astra_version` [†](#что-отклоняется) | строка | нет | `""` | Самая старая Astra, на которой работает этот плагин, как версия semver (`"0.9.0"`). |
| `call_timeout_secs` | целое | нет | отсутствует | Сколько демон ждёт `CallTool` / `ExecuteAction`, прежде чем сдаться, в секундах. |

† несёт правило, отклоняющее манифест безусловно — см.
[что отклоняется](#что-отклоняется) для условия и сообщения.

**`plugin.min_astra_version`.** Самая старая Astra, на которой работает
этот плагин, как версия semver (`"0.9.0"`). Пусто = нет требования.

Её *синтаксис* проверяется через [`PluginManifest::validate`] везде. Её
*значение* сравнивается с работающей Astra только в сборке, которая сама
её знает — см. [`crate::host_astra_version`]. Она существовала целый релиз
как поле, которое разбиралось и никогда не читалось, так что плагину,
нуждающемуся в фиче демона, которой у хоста не было, устанавливался
чисто, а затем проваливался ровно на том вызове, для которого она нужна, —
пользователь читает это как «этот плагин сломан».

**`plugin.call_timeout_secs`.** Сколько демон ждёт `CallTool` /
`ExecuteAction`, прежде чем сдаться, в секундах. `None` → собственный
`PLUGIN_CALL_TIMEOUT` демона.

Плагин, являющийся фронтом для долгоживущего агента, обязан это объявить:
значение по умолчанию демона намеренно ниже, чем «вечность», и у плагина,
чей собственный бюджет работы его превышает, результат будет выброшен,
пока его подпроцесс продолжает работать (`coding-agents` поставляет
значение по умолчанию 180 с). На плагин, так же как `McpServerConfig::timeout_secs`
— на сервер.

## `[capabilities]`

Что плагин **реализует**, демон→плагин.

**Неизвестный ключ здесь роняет весь манифест.** `Capabilities` —
`#[serde(deny_unknown_fields)]`, единственный такой среди разделов: он
целиком состоит из булевых признаков согласия, так что опечатка иначе
читалась бы ровно как `false`, и плагин установился бы, ничего не объявив.
Это не гипотеза — три примера из поставки объявляли `ui_panels`, имя,
которого никогда не было ни у одного демона, и единственным симптомом
было то, что `astra-plugin check` печатал «No capabilities enabled».

Каждый ключ — булев и по умолчанию `false`. Правая колонка — соединение с
[`spec/hooks.yaml`](../../../spec/hooks.yaml): хуки, которые ваш плагин
обязан обслуживать, чтобы возможность вообще работала. `optional`-хуки
здесь опущены; [`parity.md`](./parity.md) несёт их все.

| Ключ | Хуки, которые обязывает реализовать |
|---|---|
| `tools` | `ListTools`, `CallTool` |
| `tts` | `TtsSynthesize`, `TtsListVoices` |
| `stt` | `SttProcess`, `SttGetLanguages` |
| `ai_provider` | `AiComplete` |
| `client` | `SendChatMessage` |
| `actions` | `ExecuteAction`, `GetPluginActionTypes` |
| `triggers` | `GetPluginTriggerTypes`, `FireTrigger` |
| `ui_contributions` | `GetUiContributions` |
| `event_handlers` | `SubscribeEvents` |
| `dom_access` | нет |

**Имена, которые никогда не были настоящими:**

- `ui_panels` → `ui_contributions`

## `[permissions]`

Что плагин просит **вызывать**, плагин→демон — и это именно *просьба*.

Отсутствие означает отсутствие RPC хоста сверх всегда разрешённого
стартового набора (§5.6). Набор, который плагин реально держит, вычисляет
демон из его происхождения, и для плагина с записью доверия он никогда не
читается отсюда: манифест лежит в собственном каталоге плагина, куда
плагин может писать.

Каждый ключ — id разрешения, а каждое значение — таблица.

Id, который эта Astra не знает, сохраняется и бездействует: прямая
совместимость, а `permissions_hash` вычисляется по этим байтам тремя
реализациями, так что читатель, отбросивший нераспознанный ключ, разошёлся
бы с двумя другими насчёт того, что было подписано.

| Id | Закрывает | Свой чекбокс согласия | Отклоняется для локального импорта | Что даёт |
|---|---|---|---|---|
| `fire_trigger` | `FireTrigger` | нет | нет | Запускать сохранённые автоматизации пользователя. |
| `subscribe_events` | `SubscribeEvents` | нет | нет | Получать события демона. |
| `set_variable` | `SetVariable` | нет | нет | Писать в контекст переменных демона (в пространстве имён вызывающего плагина). |
| `send_chat_message` | `SendChatMessage` | **да** | **да** | Управлять ходом ИИ. |
| `push_to_ui` | `PushToUi` | **да** | нет | Отправлять событие в окно Astra. |
| `set_theme_contribution` | `SetThemeContribution` | **да** | **да** | Переоформлять всё приложение. |
| `dom_access` | — | **да** | **да** | Выполнять собственный код плагина внутри окна Astra, с доступом к беседам пользователя и интерфейсу любого другого плагина. |
| `client` | — | **да** | **да** | Выступать фронтендом клиента (собственная поверхность чата, собственная сессия). |

*Закрывает* — это RPC хоста, который демон отклоняет без этого разрешения,
из [`spec/hooks.yaml`](../../../spec/hooks.yaml); правило паритета R6
сверяет эту колонку с собственным `HOST_RPC_PERMISSIONS` демона — таблицей,
которую читает `require_permission`. Пустая ячейка — это разрешение
**поверхности**, не закрывающее ни один RPC: `dom_access` определяет, как
отрисовывается UI-вклад, а `client` — это потолок возможности.

*Отклоняется для локального импорта* — это потолок для файла `.astraplugin`,
который пользователь импортировал вручную, а не установил из каталога: эти
id отбрасываются безусловно, без предупреждения. Каталог с исходниками,
загруженный при включённом режиме разработчика, намеренно не ограничен
потолком — это цикл разработки для UI-плагинов.

### Значение ключа разрешения

| Ключ | Тип | Обязателен | По умолчанию | Что это |
|---|---|---|---|---|
| `reason` | строка | нет | `""` | Собственные слова автора, отрисовываемые *подчинённо* принадлежащей приложению метке (§4.3: в кавычках, простым текстом, ≤140 символов, всегда с префиксом «The author says:»). |
| `types` | массив строк | нет | пусто | `subscribe_events.types` — запрашиваемые типы событий. |
| `scopes` | массив строк | нет | пусто | `set_variable.scopes` — `"plugin"` / `"session"` / `"persistent"`. |

**`<permission>.reason`.** Собственные слова автора, отрисовываемые
*подчинённо* принадлежащей приложению метке (§4.3: в кавычках, простым
текстом, ≤140 символов, всегда с префиксом «The author says:»). Это
никогда не сама метка — формулировки фиксируются в поставке Astra и не
должны быть настраиваемы через листинг.

**`<permission>.types`.** `subscribe_events.types` — запрашиваемые типы
событий.

**Список разрешённого, и пустой не разрешает ничего.** См.
[`Permissions::event_types`].

**`<permission>.scopes`.** `set_variable.scopes` — `"plugin"` /
`"session"` / `"persistent"`. Зарезервировано; демон сегодня разделяет по
пространству имён каждую запись плагина по его id, так что это пока ничего
не сужает, но разбирается, чтобы манифест, объявляющий это, хешировался
одинаково везде.

**`fire_trigger`.** `PluginHostService.FireTrigger` — запускать
сохранённые автоматизации пользователя.

**`subscribe_events`.** `PluginHostService.SubscribeEvents` — получать
события демона.

Несёт аргумент: [`PermissionRequest::types`] — это **список разрешённого**
типов событий, и его применяет демон, а не фильтр, который отправляет
плагин. Без этого каждый подписчик получал каждое событие — включая
`speech_recognized`, которое несёт транскрипты пользователя.

**`set_variable`.** `PluginHostService.SetVariable` — писать в контекст
переменных демона (в пространстве имён вызывающего плагина).

**`send_chat_message`.** `PluginHostService.SendChatMessage` — управлять
ходом ИИ. **Высокий риск.**

**`push_to_ui`.** `PluginHostService.PushToUi` — отправлять событие в окно
Astra. **Высокий риск.**

**`set_theme_contribution`.** `PluginHostService.SetThemeContribution` —
переоформлять всё приложение. **Высокий риск.**

**`dom_access`.** Выполнять собственный код плагина внутри окна Astra, с
доступом к беседам пользователя и интерфейсу любого другого плагина.
**Высокий риск, и тот, для которого §4.3 даёт второй экран.**

**`client`.** Выступать фронтендом клиента (собственная поверхность чата,
собственная сессия). **Высокий риск.**

## `[dependencies]`

Свободная таблица `имя = "требование к версии"`. Обе половины — строки, и
крейт читает их именно так — `HashMap<String, String>`, без схемы, без
разрешения зависимостей, и ничто из неё ничего не устанавливает.
`astra-plugin check` перечисляет объявленное и предупреждает, когда
требование пустое; это весь её эффект.

## `[platform]`

| Ключ | Тип | Обязателен | По умолчанию | Что это |
|---|---|---|---|---|
| `os` | массив строк | нет | пусто | — |
| `arch` | массив строк | нет | пусто | — |

**`KNOWN_OS_VALUES`** — `linux`, `windows`, `macos`

Значения `os`, которые может называть `[platform] os = [...]`, в словаре,
на котором говорит [`current_platform`].

Шире, чем набор, для которого Astra поставляет демон: объявление
`os = ["macos"]` — это утверждение о плагине, а не заявление, что хост
существует, и валидатор, отклоняющий это, отклонял бы корректный манифест.

**`KNOWN_ARCH_VALUES`** — `x86_64`, `aarch64`

Значения `arch`, которые может называть `[platform] arch = [...]`.

**`RESERVED_PLATFORM_KEYS`** — `linux-x64`, `windows-x64`, `linux-arm64`,
`windows-arm64`, `macos-x64`, `macos-arm64`, `noarch`

Каждый ключ артефакта, зарезервированный схемой реестра, в порядке, в
котором их должен выдавать генератор.

Только [`platform_key_for`] решает, какие из них принимает *работающий
демон*, и он принимает два. Остальные зарезервированы, чтобы формат
индекса никогда не пришлось менять, если Astra позже поставит демон для
этих хостов, и чтобы валидатор реестра мог отклонить опечатку
(`mac-arm64`, `linux-amd64`) вместо того, чтобы записать ключ, который
демон никогда не станет искать.

**Зарезервировано не значит поддерживается.** Workflow релиза Astra не
собирает ни демон для macOS, ни для arm64, так что у бандла,
опубликованного под `macos-x64`, `macos-arm64`, `linux-arm64` или
`windows-arm64`, нет хоста для запуска. Генератор, выдающий такой ключ,
публикует файл, который никто не может установить.

`noarch` — это случай интерпретируемого языка (TypeScript, Python). Он
зарезервирован здесь для валидаторов, но демон его **не** ищет: согласно
спецификации бандла индекс записывает один и тот же URL и дайджест под
каждым *поддерживаемым* ключом платформы, так что `noarch`-бандл
находится под `linux-x64` / `windows-x64`, как и любой другой.

Ничто в пути выполнения демона не читает этот список — его потребители —
это генератор индекса в репозитории реестра, `check` CLI, и тест ниже,
удерживающий обе половины честными. Он лежит рядом с функцией, решающей,
какой из этих ключей настоящий, потому что это единственное место, где
эти два факта можно прочитать вместе.

## Что отклоняется

Каждый отказ, который может произвести `PluginManifest::validate`, с
условием, которое его вызывает. Условия — это сами выражения Rust:
`plugin.id` становится компонентом пути — `<plugins_dir>/<id>/`,
создаваемым и позже удаляемым через `remove_dir_all` — так что
перефразировать правило про набор символов эта страница не готова.

| Манифест отклоняется, когда | Сообщение |
|---|---|
| `self.plugin.id.is_empty()` | plugin.id is required |
| `self.plugin.name.is_empty()` | plugin.name is required |
| `self.plugin.version.is_empty()` | plugin.version is required |
| `self.entry.command.is_empty()` | entry.command is required |
| `!self.plugin.id.chars().all(\|c\| c.is_ascii_lowercase() \|\| c.is_ascii_digit() \|\| c == '-')` | plugin.id must be lowercase alphanumeric with hyphens: '{}' |
| `self.plugin.id.ends_with('.') \|\| self.plugin.id.ends_with(' ')` | plugin.id must not end with a dot or space: '{}' |
| `is_reserved_device_name(&self.plugin.id)` | plugin.id '{}' is a reserved Windows device name |
| `not (running >= required)` | Plugin '{}' requires Astra {} or newer, but this is Astra {}. Update Astra, or install a build of the plugin that supports {}. |
| ``semver::Version::parse(required)` returns Err` | plugin.min_astra_version '{}' is not a semver version (expected e.g. "0.9.0") |

`min_astra_version` — единственное правило с двумя половинами. Его
**синтаксис** проверяется везде, включая `astra-plugin check`: значение,
не являющееся версией semver, — это объявленное ограничение, которое
ничего не ограничивает. Его **значение** сравнивается только в сборке,
которая сама является Astra, — инструмент, отказывающийся смотреть на
плагин, потому что тот нацелен на более новый демон, чем сам инструмент,
был бы бессмыслицей.
