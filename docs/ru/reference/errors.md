# Справочник ошибок

Одна таксономия, четыре реализации, и эта страница — их объединение. Восемь
кодов на вызов прописаны полностью и в proto, и в каждом из трёх SDK, и
ничто не связывает их между языками на этапе компиляции — так что здесь
они сравниваются, и расхождение роняет сборку, а не превращается в
страницу, документирующую версию правды одного SDK.

## Два канала

**Внутри сообщения (in-band) — ошибка, которую читает вызывающий.**
Провалившийся инструмент произвёл результат. `NOT_CONFIGURED: OpenAI API
key is not set` — это то, что должна увидеть модель, чтобы сказать
пользователю, что делать, и то, что UI превращает в ссылку на конкретное
поле настроек. Она едет внутри сообщения ответа.

**Транспорт — gRPC `Status`.** Зарезервировано для случая, когда вызов
вообще не достиг обработчика: такого хука нет, не аутентифицирован,
соединение пропало. `UNIMPLEMENTED` означает *у этого плагина нет такого
хука* — утверждение о форме плагина, а не об этом конкретном вызове; демон
читает это как «хук отсутствует» и продолжает работу. Вернуть транспортную
ошибку для сбоя отдельного вызова — значит выбросить это различие, а для
инструмента — ещё и потерять ответ модели.

Колонка транспорта ниже — фиксированное отображение, используемое хуками,
чьё сообщение ответа не имеет поля ошибки внутри сообщения (TTS, STT, AI).
Это биекция: плагин, пробрасывающий сбой gRPC, получает обратно тот же
код, что вложил.

### `ToolError::Documented` — вариант без собственного кода

Любой из вышеперечисленных, плюс страница, документирующая именно *этот*
сбой — собственная документация плагина, или «как получить API-ключ» у
вышестоящего провайдера. Строится через [`ToolError::with_doc_url`]; UI
отрисовывает это как ссылку рядом с сообщением.

### Что значит каждый

**`BAD_ARGUMENTS`.** Аргументы не разобрались или нарушают собственный
контракт инструмента. Вызывающий может повторить с другими аргументами;
повтор с теми же не поможет. `message` называет проблемное поле.

**`NOT_FOUND`.** Адресуемая вещь не существует (неизвестное имя
инструмента, id, для которого в собственном хранилище плагина нет
строки).

**`NOT_CONFIGURED`.** Плагину нужна конфигурация, которую пользователь не
предоставил. ЕДИНСТВЕННЫЙ код, который обязан задавать `config_field`:
именно он превращает «этому инструменту нужен API-ключ» в ссылку, которая
открывает конкретное поле настроек.

**`UNAUTHORIZED`.** Собственные учётные данные плагина были отклонены тем,
с чем он общается, или вызывающему не разрешено это вызывать. Отличается
от NOT_CONFIGURED: значение ЕСТЬ, просто оно не принято.

**`RATE_LIMITED`.** Ограничение частоты — собственное плагина, или
вышестоящего сервиса. Задаёт `retry_after_ms`, когда лимит говорит,
когда.

**`UNAVAILABLE`.** Зависимость, нужная плагину, недоступна или
недостижима. Временно по умолчанию; более поздний идентичный вызов может
пройти успешно.

**`TIMEOUT`.** Плагин перестал ждать чего-то. Отличается от UNAVAILABLE
только тем, что время кончилось у плагина, а не у вызывающего.

**`INTERNAL`.** Неожиданный сбой внутри плагина — баг, паника, пойманная
SDK. Общий случай, и код, который SDK использует, когда нет ничего
лучше.

## Отказы при регистрации

Тот же enum несёт коды, которыми демон отвечает на `Register`. Плагин
никогда не производит такой код сам; он его получает и затем выходит.

| Код | Номер | Что означает |
|---|---|---|
| `PLUGIN_ERROR_PROTOCOL_TOO_OLD` | 1 | Плагин говорит на протоколе провода старше нижней границы этого демона (`PluginRegisterResponse.min_supported_protocol`). Решение всегда «пересобрать против более нового SDK»; `hint` говорит именно это, с цифрами. |
| `PLUGIN_ERROR_AUTH` | 2 | `auth_token` времени запуска отсутствовал или не совпал. |
| `PLUGIN_ERROR_UNKNOWN_PLUGIN` | 3 | Демон не знает такого id плагина, либо он не в состоянии, допускающем регистрацию. |

`PLUGIN_ERROR_UNSPECIFIED = 0` — нулевое значение proto3 и означает, что
отправитель ничего не задал.

## Какие поля несёт ошибка

| Поле | Для | Что это |
|---|---|---|
| `code` | каждого кода | Один из кодов выше. |
| `message` | каждого кода | Что пошло не так. |
| `hint` | каждого кода | Что с этим ДЕЛАТЬ. |
| `config_field` | `NOT_CONFIGURED` | Цель для глубокой ссылки: поле конфига плагина, которое должен заполнить пользователь, названное точно так, как оно указано в схеме конфигурации плагина (`api_key`, `account.token`). |
| `retry_after_ms` | `RATE_LIMITED` | Сколько ждать перед повтором, в миллисекундах. |
| `doc_url` | каждого кода | Страница, документирующая именно ЭТОТ сбой — собственная документация плагина, «как получить API-ключ» у вышестоящего провайдера. |

Обе половины отправляются всегда. Структурированное сообщение — это
добавление, а не замена: плагин, собранный против более старого протокола,
не отправляет структурированных подробностей, а собранный против этого
протокола, но говорящий со старым демоном, — их отбрасывает парсер
получателя. В обоих направлениях человекочитаемая строка выживает, так
что обе пары продолжают работать — именно поэтому строка снабжена
префиксом с кодом (`NOT_CONFIGURED: …`): именно этот префикс говорит циклу
ИИ прекратить повторы.

## Отсутствующие хуки — не ошибки

«У этого плагина нет такого хука.»

Каждый хук со значением по умолчанию, у которого нет разумного отката,
возвращает это, и `runner.rs` превращает это в `Status::unimplemented` —
слово протокола для *отсутствия*, которое хелпер демона `optional_hook`
читает именно так (`astra-daemon/src/plugins/manager.rs`). Это намеренно
отличается от [`ToolError::Internal`]: «у меня нет TTS» и «мой TTS упал» —
у этого разные последствия, и ответ вторым, когда имеешь в виду первое,
заставляет демона пометить рабочий плагин мёртвым.
