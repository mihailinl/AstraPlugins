# Плагины музыкальных сервисов

> Перевод. Источник истины — [docs/en](../en/music-provider-plugins.md); при расхождении верна английская версия.

Плагин музыкального сервиса объявляет `music_provider = true` в разделе
`[capabilities]` своего `plugin.toml`. После этого он становится источником
**медиасессий** для Astra: музыкальный виджет, Dynamic Island и медиаинструменты
ассистента (`get_now_playing`, `control_media`, `play_music`, `get_music_queue`)
дотягиваются до сервисов, с которыми он работает, — Web API Spotify, локальный API
десктопного плеера, мост в браузер — и могут поставить лайк В САМОМ сервисе,
прочитать его очередь, искать в каталоге и запускать воспроизведение там.

Плагин не рисует для этого никакого интерфейса — это делает плеер самой Astra.

## Что делает Astra, чтобы этого не делал плагин

Всё вокруг плагина берёт на себя медиахаб демона:

- **Сопоставление.** Когда сервис играет на этом компьютере, у ОС обычно есть
  медиасессия той же самой игры (приложение Spotify, вкладка браузера). Хаб
  связывает их, и одна песня — одна сессия: сессия ОС получает ваш лайк и очередь,
  ничего не показывается дважды. ОС остаётся источником истины о том, что
  СЛЫШНО: ваши название, обложка и позиция её не перезаписывают.
- **Удалённые сессии.** Сессия, которую вы помечаете как играющую НЕ на этом
  устройстве (телефон, колонка), показывается отдельно, с пометкой «удалённая».
  Она никогда не выдаётся за «этот компьютер» — остров её не показывает.
- **Маршрутизация.** Для связанной сессии play/pause/next/seek идут через ОС —
  так работает любое приложение; лайк, снятие лайка, перемешивание, повтор,
  громкость, очередь и запуск идут к вам.
- **Границы и безопасность.** Обложки скачивает демон (только https и никогда —
  сеть этого компьютера); ссылки — https или известная схема приложения; строки
  и списки обрезаются; всё, что модель читает от вас, помечается как текст
  из недоверенного источника.

Поэтому плагин только сообщает, что играет каждый сервис, и выполняет по одному
действию за раз.

## Создайте провайдер

<!-- doctest: cli -->
```bash
astra-plugin new my-music --lang python --template blank --capabilities music_provider --output ./my-music
```

`--lang` может быть и `rust`, и `typescript`. Отдельного музыкального шаблона
нет: возможность приходит через `--capabilities`, а `music_control` в заготовке
отвечает `not_configured`, пока вы его не реализуете. `astra-plugin test`
проверяет хуки с сессией и элементом, которых ни один плагин не сообщает. На ключ
сессии, который ваш плагин не публиковал, SDK отвечает `not_found` ещё до вашего
хука, поэтому проба не может поставить на паузу или лайкнуть что-то на вашем
собственном плеере. Исключение — `MusicSearch`: он отправляет настоящий запрос,
и плагин с выполненным входом ответит из живого сервиса (поиск ничего не меняет).

Укажите `min_astra_version`: `[capabilities]` — закрытый набор, и Astra старше
той, где появился `music_provider`, отклонит весь манифест.

## Отчёт: публикуйте весь набор целиком

Отчёт — это push. Каждый SDK держит публикатор — `self.music` в Python и
TypeScript, `MusicPublisher`, который вы возвращаете из `music_publisher`, в Rust —
и обслуживает из него долгоживущий поток `MusicSubscribe` демона: последний снимок
сразу, снова при каждой публикации и каждые `music_snapshot_heartbeat_secs`
(15 с), чтобы заметить замолчавший плагин. Снимку старше
`music_session_stale_secs` (45 с) демон больше не верит.

**Каждая публикация — это ВЕСЬ набор.** Сессия, которую вы не включили, закончилась.

<!-- doctest: illustrative reason="needs a running service account; shows the publish call shape only" -->
```python
self.music.publish(
    [MusicService("spotify", "Spotify", can_search=True, can_play=True)],
    [MusicSession(
        session_key="spotify",
        service_id="spotify",
        this_device=True,
        device_name="DESKTOP-1",
        exclusive_app_hints=["spotify", "spotify.exe"],
        status="playing",
        title="Believer",
        artist="Imagine Dragons",
        artwork_url="https://i.scdn.co/image/…",
        position_seconds=42.0,
        duration_seconds=204.0,
        liked=True,
        controls=["play", "pause", "next", "previous", "seek", "like", "unlike", "queue", "play_into"],
    )],
)
```

Поля, от которых зависит сопоставление:

| Поле | Значение |
|---|---|
| `this_device` | звук может идти из ЭТОГО компьютера. Только такая сессия может связаться с сессией ОС |
| `exclusive_app_hints` | идентификаторы сессий ОС у приложения, которое не играет ничего, кроме этого сервиса, — исполняемый файл Spotify, имя MPRIS-плеера. Совпадения достаточно |
| `shared_app_hints` | хосты многого сразу, например браузеры. Связь возникает, только если совпадают и название, и исполнитель |

Подсказка сравнивается без учёта регистра с идентификатором сессии ОС, его
последним сегментом пути или AppUserModelId, этим сегментом без `.exe` и именем
MPRIS-плеера — поэтому `spotify` одинаково называет `C:\…\Spotify.exe`,
`SpotifyAB.SpotifyMusic_zpdnekdrzrea0!Spotify` и `org.mpris.MediaPlayer2.spotify`.

`controls` перечисляет глаголы сессии из фиксированного списка; всё остальное
демон отбрасывает: `play`, `pause`,
`next`, `previous`, `seek`, `like`, `unlike`, `shuffle`, `repeat`, `volume`,
`queue` (вы отвечаете на `MusicGetQueue`) и `play_into` (вы отвечаете на
`MusicPlay`).

## Ответы: четыре хука

| Хук | Обязательность | Что делает |
|---|---|---|
| `MusicControl` | обязателен | одно действие над одной сессией; `value` содержит секунды для `seek`, `0`–`100` для `volume`, `on`/`off` для `shuffle`, `off`/`track`/`context` для `repeat` |
| `MusicGetQueue` | необязателен | очередь сессии вокруг играющего элемента, с `current_index` |
| `MusicSearch` | необязателен | поиск по каталогу; `item_ref` каждого элемента — ваш собственный и возвращается в `MusicPlay` |
| `MusicPlay` | необязателен | запустить элемент или первое совпадение по словам — `mode` бывает `now`, `next` или `end` |

**Отказ, который вы имеете в виду, — это ответ**, а не ошибка: пользователь не
вошёл, сервис требует подписку, нигде ничего не играет. Бросьте или верните
отказ SDK — `MusicRefusal` во всех трёх — с одним из кодов `not_supported`,
`not_found`, `no_active_device`, `auth`, `premium_required`, `rate_limited`,
`unavailable`, `not_configured`. Демон покажет его человеку на его языке. Любая
другая ошибка означает, что плагин сломан.

<!-- doctest: illustrative reason="the service calls are placeholders; shows the refusal shape only" -->
```python
async def music_control(self, request):
    if not self.signed_in:
        raise MusicRefusal(MusicErrorCode.NOT_CONFIGURED, "Connect Spotify in the plugin's settings")
    device = self.devices.get(request.session_key)  # act on THE session named
    if device is None:
        raise MusicRefusal(MusicErrorCode.NOT_FOUND, "That player has gone")
    await device.do(request.action, request.value)
```

## Где легко ошибиться

- **Сообщайте позицию такой, как прочитали, без экстраполяции вперёд.** Демон сам
  экстраполирует играющую сессию от момента, когда эта позиция пришла впервые:
  сессия, присланная повторно без изменений (так делает heartbeat), сохраняет
  отметку, а новая позиция её обновляет.
- **Держите ключи сессий стабильными** (`[A-Za-z0-9._-]{1,64}`), пока это та же
  самая игра; новый ключ — новая сессия.
- **Не объявляйте вкладку браузера эксклюзивной.** Браузер играет многое; такой
  хинт повесит ваш лайк на чьё-то видео.
- **Не храните токены входа в `[config]`.** Astra хранит конфиг как обычный JSON
  и показывает его на странице плагинов; используйте keyring ОС.
