# Примеры

> Перевод. Источник истины — [docs/en](../../en/7-examples/README.md); при расхождении верна английская версия.

Одиннадцать плагинов в [`examples/`](../../../examples/), все перенесены на
текущие SDK и все собираются в CI. Читайте тот, что делает то, что нужно
вам, а затем начинайте с заготовки, а не с примера — примеры не несут
шаблонного кода, который вам пришлось бы удалять.

Каждая запись ниже читается из собственного `plugin.toml` этого плагина.

## С чего читать в первую очередь

| | Язык | Возможности | Разрешения | Почему именно этот |
|---|---|---|---|---|
| [`dice-roller`](../../../examples/dice-roller/) | Rust | `tools`, `actions`, `triggers` | `fire_trigger` | Эталонный плагин. Три возможности, одно разрешение, и набор тестов, показывающий, как тестируется каждая |
| [`json-tools`](../../../examples/json-tools/) | TypeScript | `tools`, `actions`, `triggers` | `set_variable` | Та же форма на TypeScript, и пример, чьи тесты доходят до уровня провода |
| [`text-utils`](../../../examples/text-utils/) | Python | `tools`, `actions`, `triggers` | `fire_trigger` | Та же форма на Python |

Эти три — намеренно один и тот же плагин тремя способами. Если вы выбираете
язык, прочтите все три и выберите экосистему, из которой хотите тянуть
библиотеки — каждая возможность доступна в каждом SDK.

## Голосовые провайдеры

| | Язык | Возможности | Почему именно этот |
|---|---|---|---|
| [`tone-tts`](../../../examples/tone-tts/) | Rust | `tts` | Провайдер синтеза речи, говорящий писками. Тест проводки, а не голос |
| [`mock-stt`](../../../examples/mock-stt/) | Rust | `stt` | Возвращает детерминированный транскрипт, описывающий полученное аудио. Bidi-поток минус распознаватель |
| [`echo-stt`](../../../examples/echo-stt/) | Rust | `stt` | Ничего не транскрибирует и проигрывает ваш микрофон обратно через процесс плагина. Чтобы услышать, что демон реально вам отправляет |

`tone-tts` и `mock-stt` — два из четырёх плагинов, которые задача проверки
соответствия прогоняет на каждом запуске CI, именно потому что они
упражняют хуки, которые больше никто не трогает.

## UI и `dom_access`

Эти запускают код внутри окна Astra. Именно из-за них
[у сайдлоадинга нет потолка разрешений](../5-publish/sideload.md):
`dom_access` невозможно разрабатывать никаким другим способом.

| | Язык | Возможности | Почему именно этот |
|---|---|---|---|
| [`companion`](../../../examples/companion/) | Rust | `ui_contributions`, `dom_access` | Кошка, летающая по окну и что-то говорящая. Наименьший полный UI-вклад |
| [`bad-apple`](../../../examples/bad-apple/) | Rust | `ui_contributions`, `dom_access` | Анимация *Bad Apple!!* в четырёх режимах отрисовки. Поставляет собственные данные кадров; см. её `SETUP.md` |
| [`doom`](../../../examples/doom/) | Rust | `ui_contributions`, `dom_access` | Страница с Doom, работающая на WebAssembly-движке. Самое крайнее, чем может быть UI-вклад |

`companion` — четвёртый плагин, который прогоняет задача проверки
соответствия, для `ui_contributions`.

## Клиенты

Плагин `client` — это собственный фронтенд чата — своя сессия, своя
поверхность. Это высокорисковая возможность, и она отклоняется безусловно
для [локально импортированного файла](../5-publish/local-install.md).

> **Оба этих примера опережают демон.** Половина клиентского пути на
> стороне демона не построена: каждый плагин регистрируется как
> `ClientType::PluginClient`, и перехватчик авторизации отклоняет эту
> идентичность на любом gRPC-пути вне `/astra.PluginHostService/`. Так что
> `DaemonClient`, под который написаны эти два примера, отвечает
> `permission_denied` на каждый вызов. Читайте их ради формы клиентского
> плагина — поверхности, потока событий, i18n, — а не как то, что сегодня
> можно запустить от начала до конца. См.
> [раздел `Daemon` Rust SDK](../4-sdk/rust.md#daemon--присутствует-в-sdk-отклоняется-демоном).

| | Язык | Возможности | Почему именно этот |
|---|---|---|---|
| [`telegram-client`](../../../examples/telegram-client/) | Rust | `client` | Каждый разговор Astra становится темой в Telegram, с потоковыми ответами |
| [`web-chat`](../../../examples/web-chat/) | Rust | `client` | Окно браузера, общающееся с Astra. Чтобы понаблюдать за синхронизацией нескольких клиентов |

## Платформы

Ни один из одиннадцати не объявляет блок `[platform]`, а значит демон
считает каждый совместимым везде — верно для двух интерпретируемых, и то,
что *опубликованный* нативный плагин должен бы сузить. См.
[платформы](../1-orientation/platforms.md).

| Язык | Что собирает релиз |
|---|---|
| Rust (девять из них) | `linux-x64` **и** `windows-x64`, по одному бандлу на каждую |
| TypeScript (`json-tools`) | один бандл `noarch` |
| Python (`text-utils`) | один бандл `noarch` |

`doom` и `bad-apple` дополнительно поставляют данные — WebAssembly-движок,
несколько мегабайт кадров — и их `SETUP.md` говорит, откуда они и как их
регенерировать.

## Чем они протестированы

| Уровень | Что запускается | Какие примеры |
|---|---|---|
| Юнит | внутрипроцессный harness SDK, в собственных тестах каждого примера | `dice-roller`, `mock-stt`, `text-utils`, `json-tools` |
| Сборка | каждый пример собирается на каждом запуске CI | все одиннадцать |
| Соответствие | `astra-plugin test` запускает настоящий процесс против мок-демона и прогоняет каждый хук, который подразумевают его возможности | `dice-roller`, `mock-stt`, `tone-tts`, `companion` |

Набор для проверки соответствия выбран ради покрытия таблицы хуков, а не
ради разнообразия — tools/actions/triggers, bidi-поток STT, TTS и
UI-вклады. **У `ai_provider` нет примера, и поэтому он не покрыт**, и об
этом стоит сказать вслух: пробел в покрытии, который никто не называет,
становится тем, который все считают закрытым.

Примеры на Python и TypeScript пока не в задаче проверки соответствия,
потому что их SDK не опубликованы, а прогон проверки соответствия, который
наполовину устанавливает SDK, отчитывается об установке, а не о плагине.
`astra-plugin test` управляет процессом и ей неважно, на каком языке он
написан, так что они присоединятся к задаче в тот день, когда SDK будут
опубликованы.

## Запуск одного из них

<!-- doctest: cli -->
```bash
cd examples/dice-roller
astra-plugin check --strict
astra-plugin test
astra-plugin dev
```

`dev` требует запущенной Astra и режима разработчика — сначала прочтите,
[чего это стоит](../5-publish/sideload.md).
