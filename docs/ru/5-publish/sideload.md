# Сайдлоад — инструмент разработчика

> **Так плагины не устанавливают.** Сайдлоад указывает Astra на каталог с
> исходниками у вас на диске и запускает его — неподписанным, нативным
> процессом с полными правами вашей учётной записи. Он существует, чтобы вы
> могли разрабатывать плагин. Он закрыт явным переключателем, и этот
> переключатель снижает планку для **каждого** плагина на машине, а не только
> для вашего.
>
> Пользователи ставят плагины из самой Astra. Авторы публикуют через
> [`init-ci` и тег](release-with-ci.md), а затем
> [один раз попадают в каталог](get-listed.md).

Никогда не сайдлоадьте плагин, который вы не писали и не читали. Если кто-то
прислал вам каталог и инструкцию включить режим разработчика — вас просят
запустить их код от вашего имени.

## Как включить

Сайдлоад отклоняется, пока `safety.allow_unsigned_plugins` не включён. Демон
говорит это ровно такими словами:

<!-- doctest: illustrative reason="отказ демона, цитата из astra-daemon/src/plugins/manager.rs; чтобы его воспроизвести, нужна работающая Astra с выключенной настройкой" -->
```
Sideloading is disabled. It runs an unsigned local plugin as native code with
your full privileges. Turn on Settings -> Privacy -> "Allow unsigned plugins"
(`safety.allow_unsigned_plugins`) to sideload (local plugin development only).
```

а CLI превращает это в ту же инструкцию с исправлением на отдельной строке
(`astra-plugin-cli/src/daemon.rs`). Два сообщения называют разные разделы
настроек — демон говорит Privacy, CLI говорит Safety. **Ключ настройки —
`safety.allow_unsigned_plugins`**, и искать нужно именно его.

## Как пользоваться

<!-- doctest: cli -->
```bash
astra-plugin dev
astra-plugin dev . --daemon-addr 127.0.0.1:32000
```

`dev` делает четыре вещи по порядку и останавливается на первой неудаче:

1. `astra-plugin check --strict` — он не отдаст демону манифест, который уже
   неверен;
2. собирает;
3. отдаёт **каталог** демону через `SideloadPlugin`; тот запускает процесс,
   выпускает токен аутентификации и дальше владеет жизненным циклом;
4. следит за изменениями, пересобирает, останавливает и запускает плагин заново
   и показывает его вывод.

<!-- doctest: output from="astra-plugin dev . без запущенной Astra" -->
```
Dev mode: plugin 'dice-roller'
  Directory: /tmp/dice-roller
Checking plugin at /tmp/dice-roller...
  OK: plugin 'dice-roller' v0.1.0 is valid (0 warning(s), 2 note(s), capabilities: tools)
  Running cargo build --release...
    Finished `release` profile [optimized] target(s) in 2.48s
Error: Could not read /home/you/.config/astra/daemon.token. Astra does not look
like it is running — start the app first.
```

**Процессом владеет демон, и это не вопрос стиля.** Плагин аутентифицируется в
`PluginHostService` токеном, который демон выпускает, когда сам запускает
процесс, и демон отвергает любой `Register` без выданного им токена. У плагина,
запущенного из CLI, взять такой токен неоткуда — предыдущий самозапускающийся
dev-цикл поднимал процесс, который ни с кем не разговаривал.

`--standalone` сохраняет прежнее поведение для случаев, когда оно всё ещё
полезно (проверить, что бинарник стартует, погонять его руками), и сразу
сообщает, чего так сделать нельзя.

`dev --json` намеренно отвергается: `--json` обещает один документ на запуск, а
`dev` не завершается. Машиночитаемые половины того, что он делает, — это
`astra-plugin check --json`, `astra-plugin test --json` и
`astra-plugin logs --json`.

## Чего именно стоит сайдлоад

| | |
|---|---|
| **Подпись** | никакой. За код никто не ручается |
| **Права** | полные права вашей учётной записи. Песочницы нет — [фазы 7 не существует](../1-orientation/security.md) |
| **Радиус поражения переключателя** | `allow_unsigned_plugins` действует на все плагины на машине, включая неподписанные файлы, которые вы импортируете позже |
| **Автозапуск** | **никогда.** Режим разработчика нужен в момент загрузки, и после перезапуска сайдлоаженный плагин остаётся остановленным, пока вы не запустите его снова |
| **Потолок разрешений** | **нет** — см. ниже |
| **Происхождение, показываемое пользователю** | уровень `sideloaded` — «загружен из папки» — в панели происхождения |

### Почему здесь нет потолка разрешений

У [локально импортированного `.astraplugin`](local-install.md) четыре
разрешения отклоняются наотрез. У сайдлоаженного **каталога с исходниками** —
нет, и это исключение сделано намеренно: это цикл разработки UI-плагинов, а
`dom_access` — ровно то, что нужно `companion`, `doom` и `bad-apple`. Потолок на
уровне 3 сделал бы их неразрабатываемыми.

Взамен уровень 3 закрыт явной настройкой, никогда не стартует сам и представляет
собой каталог, на который вы указали лично, — три факта, которых уровень 2 (файл,
пришедший откуда-то) предъявить не может.

План также требует постоянного, несбрасываемого значка «DEVELOPER — непроверенный
код из локального каталога» на карточке плагина и на рамке окна, пока активен
`dom_access`. **Этого значка сегодня в интерфейсе нет**, и эта страница не
утверждает обратного.

## Что не работает и работать не будет

**Ручная запись маркера `sideload.json` в каталог плагинов.** Демон отвергает
маркер, о выдаче которого у него нет записи:

<!-- doctest: illustrative reason="строка лога демона, цитата из astra-daemon/src/plugins/manager.rs; она появляется на машине с подложенным маркером" -->
```
Refusing sideload marker in <path>: this daemon never authorised a sideload of
'<id>' from <source> (no matching record in <registry path>). A marker file
alone does not authorise running unsigned native code.
```

Старые инструкции советовали положить маркер в
`~/.config/astra/astra/plugins` — путь, которого не существует, поверх
механизма, который больше не работает, и без упоминания обязательного
`allow_unsigned_plugins`. Они удалены, а не исправлены. Замена — одна строка:
`astra-plugin dev`.

## Когда разработка закончена

Ничто на этом пути не даёт того, что сможет установить другой человек. Чтобы
выпустить:

1. [`astra-plugin init-ci`](release-with-ci.md), затем тег — CI соберёт и
   аттестует;
2. [`astra-plugin publish`](get-listed.md) — один раз навсегда;
3. пользователи ставят из самой Astra, а дайджест закреплён.

Выключить `allow_unsigned_plugins`, когда вы не разрабатываете, стоит двух
кликов.
