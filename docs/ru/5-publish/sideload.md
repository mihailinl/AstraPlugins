# Сайдлоадинг — инструмент разработчика

> Перевод. Источник истины — [docs/en](../../en/5-publish/sideload.md); при расхождении верна английская версия.

> **Это не то, как устанавливаются плагины.** Сайдлоадинг указывает Astra на
> каталог с исходниками на вашем диске и запускает его, неподписанным, как
> нативный процесс с правами вашей полной учётной записи. Он существует,
> чтобы вы могли разрабатывать плагин. Он за явным включением, и это
> включение снижает планку для **каждого** плагина на машине, а не только
> вашего.
>
> Пользователи устанавливают изнутри Astra. Авторы публикуют через
> [`init-ci` и тег](release-with-ci.md), а затем
> [попадают в каталог один раз](get-listed.md) —
> [весь путь на одной странице](../publishing.md).
>
> Сказать кому-то клонировать ваш репозиторий и сайдлоаднуть его — это не
> публикация. Это просьба запустить неподписанный код от своего имени, и она
> достигает ровно тех людей, с которыми вы можете поговорить.

Никогда не сайдлоадьте плагин, который вы не писали и не проверяли. Если
кто-то присылает вам каталог и инструкцию включить режим разработчика, он
просит вас запустить его код от вашего имени.

## Как включить

Сайдлоадинг отклоняется, если `safety.allow_unsigned_plugins` не `true`.
Демон говорит об этом ровно так:

<!-- doctest: illustrative reason="the daemon's refusal, quoted from astra-daemon/src/plugins/manager.rs; reproducing it needs a running Astra with the setting off" -->
```
Sideloading is disabled. It runs an unsigned local plugin as native code with
your full privileges. Turn on Settings -> Privacy -> "Allow unsigned plugins"
(`safety.allow_unsigned_plugins`) to sideload (local plugin development only).
```

а CLI превращает это в ту же инструкцию с решением на отдельной строке
(`astra-plugin-cli/src/daemon.rs`). Два сообщения называют разные разделы
настроек — демон говорит Privacy, CLI говорит Safety. **Ключ настройки —
`safety.allow_unsigned_plugins`**, и именно его нужно искать.

## Как использовать

Одна команда, из [CLI](../install-cli.md):

<!-- doctest: cli -->
```bash
astra-plugin dev
astra-plugin dev . --daemon-addr 127.0.0.1:32000
```

`dev` делает четыре вещи по порядку и останавливается на первом же сбое:

1. `astra-plugin check --strict` — она не передаст демону манифест, который
   уже неправильный;
2. собирает;
3. передаёт **каталог** демону через `SideloadPlugin`, который запускает
   процесс, выпускает его токен авторизации и с этого момента владеет его
   жизненным циклом;
4. следит за изменениями, пересобирает, останавливает/запускает плагин и
   хвостом читает его вывод.

<!-- doctest: output from="astra-plugin dev . with no Astra running" -->
```
Dev mode: plugin 'dice-roller'
  Directory: /tmp/dice-roller
Checking plugin at /tmp/dice-roller...
  OK: plugin 'dice-roller' v0.1.0 is valid (0 warning(s), 2 note(s), capabilities: tools)
  Running cargo build --release...
    Finished `release` profile [optimized] target(s) in 2.48s
Error: Could not read /home/you/.config/astra/daemon.token. Astra does not look
like it is running — start the app first.
```

**Демон владеет процессом, и это не стилистическое решение.** Плагин
аутентифицируется в `PluginHostService` токеном, который демон выпускает,
когда запускает процесс, и демон отклоняет любой `Register`, не несущий
токена, который он сам выпустил. У плагина, запущенного CLI, нет способа
его получить — самозапускающийся цикл разработки, который это заменило,
запускал процесс, который ни с кем не общался.

`--standalone` сохраняет то старое поведение для случаев, где оно всё ещё
полезно (проверить, что бинарник запускается, покрутить его вручную), и
сразу говорит, что таким образом плагин не может зарегистрироваться в
Astra.

`dev --json` отклоняется намеренно: `--json` обещает один документ на
запуск, а `dev` никогда не завершается. `astra-plugin check --json`,
`astra-plugin test --json` и `astra-plugin logs --json` — это
машиночитаемые половины того, что она делает.

## Чего стоит сайдлоадинг, точно

| | |
|---|---|
| **Подпись** | никакой. Ничто не поручается за код |
| **Права** | ваша полная учётная запись пользователя. Песочницы нет — [фазы 7 не существует](../1-orientation/security.md) |
| **Радиус поражения переключателя** | `allow_unsigned_plugins` применяется к каждому плагину на машине, включая неподписанные файлы, которые вы импортируете позже |
| **Автозапуск** | **никогда.** Режим разработчика нужен в момент загрузки, и перезапуск оставляет сайдлоаднутый плагин остановленным, пока вы не запустите его снова |
| **Потолок разрешений** | **никакого** — см. ниже |
| **Происхождение, показываемое пользователю** | уровень `sideloaded` — «загружено из папки» — в панели происхождения |

### Почему здесь нет потолка разрешений

У [локально импортированного `.astraplugin`](local-install.md) четыре
разрешения отклоняются безусловно. У сайдлоаднутого **каталога с
исходниками** — нет, и это исключение намеренное, а не недосмотр: это цикл
разработки для UI-плагинов, и `dom_access` — это ровно то, что нужно
`companion`, `doom` и `bad-apple`. Ограничить потолком уровень 3 сделало бы
их неразрабатываемыми.

Компромисс в том, что уровень 3 закрыт за явной настройкой, никогда не
запускается автоматически и является каталогом, на который вы указали сами
— три факта, которые уровень 2 (файл, пришедший откуда-то) заявить не
может.

План также просит постоянный, неубираемый бейдж «РАЗРАБОТЧИК —
неверифицированный код из локального каталога» на карточке плагина и на
рамке окна всякий раз, когда активен `dom_access`. **Этого бейджа сегодня
нет в интерфейсе**, и эта страница не утверждает обратного.

## Что не работает и не будет работать

**Ручное создание маркера `sideload.json` в каталоге плагинов.** Демон
отклоняет маркер, о котором у него нет записи авторизации:

<!-- doctest: illustrative reason="a daemon log line, quoted from astra-daemon/src/plugins/manager.rs; it is emitted on a machine with a planted marker" -->
```
Refusing sideload marker in <path>: this daemon never authorised a sideload of
'<id>' from <source> (no matching record in <registry path>). A marker file
alone does not authorise running unsigned native code.
```

Более старые инструкции говорили авторам подложить маркер в
`~/.config/astra/astra/plugins` — путь, которого не существует, поверх
механизма, который больше не работает, без упоминания предпосылки
`allow_unsigned_plugins`. Они были удалены, а не исправлены. Замена — одна
строка: `astra-plugin dev`.

## Когда вы закончили разработку

Ничего в этом пути не производит то, что может установить другой человек.
Чтобы выпустить релиз:

1. [`astra-plugin init-ci`](release-with-ci.md), затем тег — CI собирает и
   удостоверяет его;
2. [`astra-plugin publish`](get-listed.md) — один раз, навсегда;
3. пользователи устанавливают его изнутри Astra, с закреплённым дайджестом.

Выключить `allow_unsigned_plugins` обратно, когда вы не разрабатываете,
стоит этих двух кликов.
