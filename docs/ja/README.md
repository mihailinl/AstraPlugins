# Astra プラグイン ドキュメント

プラグインとは、Astra が起動して gRPC 経由で対話する独立したプログラムです。プラグインは
モデルにツールを提供したり、テキスト読み上げ(TTS)や音声認識(STT)エンジンを提供したり、
コマンドエディタにステップやトリガーを追加したり、UI に貢献したり、あるいは自分自身の
チャットクライアントとして振る舞ったりできます。

ここには 2 つの読み進め方があり、このページのすべての項目はどちらかに属します。

## プラグインを公開する

**公開とは、GitHub の CI がビルドし証明したタグ付きリリースに、1 回きりのリスティング申請を
加えたものです。それだけです。** ソースを GitHub に push することは公開ではありません。
zip を誰かに送ることも公開ではありません。メンテナーにビルドを頼むことも公開ではありません。
レジストリは、ユーザーがダウンロードして読み込む正確なファイルのダイジェストでプラグインを
固定し、GitHub のビルド証明を読んでどのワークフロー・コミット・リポジトリがそのバイト列を
生成したかを確認します — 自分のラップトップでビルドしたファイルには、そのどちらもありません。

| | |
|---|---|
| **[プラグインを公開する](publishing.md)** | **空のディレクトリからリスト掲載までの全行程を 1 ページで、すべてのコマンドと出力付き。まずはここから。** |
| [CLI をインストールする](install-cli.md) | ビルド済みの `astra-plugin` をダウンロードして検証するか、ソースからビルドしてください。`cargo install` ではありません — それがうまくいかない理由もここに書いてあります |

段階を踏んで見たい場合は、次の 3 段階です。

1. [CI でリリースする](5-publish/release-with-ci.md) — `astra-plugin init-ci` を実行してからタグを打つ。GitHub がバンドルをビルドし証明する。
2. [リストに掲載してもらう](5-publish/get-listed.md) — 1 回きりの申請。以後のリリースはノータッチになる。
3. ユーザーは Astra の中からインストールする。アーティファクトはダイジェストで固定される。

プラグインをマシンに乗せる方法は他に 2 つあります。**どちらも公開ではありません。**
どちらも開発者向けで、どちらも代償があり、それぞれ何をするかがはっきりしています。

- [ローカルファイルをインストールする](5-publish/local-install.md) — 帯域外で受け取った `.astraplugin`。4 つのパーミッションは無条件で拒否されます。
- [ソースディレクトリをサイドロードする](5-publish/sideload.md) — 開発中のループ用。開発者モードが必要で、あなたのフルユーザー権限で未署名コードを実行します。

その他: [バージョニングと非推奨ポリシー](versioning.md) · [0.6 への移行](migration-0.6.md)

リファレンスページはインターフェースの定義がもう 1 つ増えることを意味し、そしてそれは
常に間違っている側のほうです。

## 言語

英語が正式版です。その隣に 6 つの翻訳があり、いずれもこのドキュメントを
ファイル単位でミラーしたものです — 同じファイル、同じ見出し、同じ順序:

[Deutsch](../de/README.md) · [Español](../es/README.md) · [日本語](README.md) · [Русский](../ru/README.md) · [Українська](../uk/README.md) · [简体中文](../zh/README.md)

CI が検査するのは翻訳の「形」です。`docs/en` とまったく同じページが揃っていること、
すべてのリンクが解決すること、そしてコードブロックが今も動くこと。
同一のブロックは一度だけ実行され英語版と `identical to` と報告されるので、
翻訳の過程でずれたブロックは自分の分として改めて実行されます。
CI には、ある文が英語の文と同じ意味を保っているかどうかは検査できません。
だから食い違ったときは英語が優先され、翻訳された各ページは冒頭でそう述べています。
どのページへの修正も歓迎します。

## このドキュメント全体が気をつけている 2 つのこと

**プラグインはサンドボックス化されていません。** プラグインはあなたとして動くネイティブ
プロセスであり、あなたのファイルとネットワークにアクセスできます。署名が答えるのは
*誰がこのバイト列を公開したか*であり、パーミッションが答えるのは*プラグインが要求した
ときにデーモンが何をするか*です。どちらも、そのプロセスがあなたのマシンに対して何が
できるかには答えません。[セキュリティモデル](1-orientation/security.md) を参照してください。

**信頼チェーンはデリゲーションまでは固定されていますが、カタログまではまだです。**
ルートキーは存在し両側で一致しており、インデックス署名キーに委譲する root 署名済みの
`trust.json` も今では存在します — `astra-root-2026a` の下で検証され、レジストリがビルド
証明として受け入れる再利用可能ワークフローのコミットを 1 つ名指ししています。まだ欠けて
いるのはカタログ自身の署名です。`registry/v1/index.json` と `revocations.json` は
`"signatures": []` を持っており、デフォルトビルドにはチェックするものが何もなく、
フェイルクローズし、すべてのカタログを未署名として分類します。これは
[`spec/registry-index.md` §0.1](spec/registry-index.md) に書かれており、関係する箇所では
静かに省略されることなく繰り返し述べられています。
